## 二、混乱点小结

1. **文档三处散落**：根目录 / `TODO/` / `tasks/` 三套并存，边界不清。
2. **命名打架**：`TODO/TODO.md` 与 `tasks/todo.md`。
3. **历史版本混在部署目录**：v1 / v2 / 副本 与当前要上传的 `growth-schoolv3.html` 并排放在根目录，容易被误打包或误上传。
4. **本地杂物干扰 git 视图**：3.8MB 未跟踪文件，且里面还有 `*.png`，会被 `build-deploy.ps1` 的"未跟踪新增"扫到（危险）。
5. **构建产物夹带密钥**：`releases/deploy/…/eggworld.jar` 32MB，内含本地配置。
6. **测试两套并列**：`tests/`（前端）与 `backend/src/test/`（后端）。

## 四、分阶段执行计划

### 阶段 1：归拢本地杂物到 `local-only/`（不删除）

```powershell
# 1) 先建目录并把它加进 .gitignore（必须先做，否则里面的 *.png 会被打包脚本当成"新增前端文件"）
New-Item -ItemType Directory -Force -Path local-only
# .gitignore 追加：local-only/

# 2) 移动（用 Move-Item，不删）
Move-Item images-original, new, 'onboard-guide-package(1)', '线上服务器数据' local-only/
Move-Item 1.html, unlock-character-package.txt, 'growth-schoolv1 - 副本.html' local-only/
```

- **风险**：零（全是未跟踪文件）
- **必配动作**：`.gitignore` 新增 `local-only/`；确认旧规则可保留（也可清理，二者不冲突）
- **顺带**：删除 `releases/deploy/2026-09-13_…/`（32MB，含密钥的旧包）——**待你确认是否一并删**

### 阶段 2：历史版本归档到 `archive/`

```powershell
New-Item -ItemType Directory -Force -Path archive
git mv growth-schoolv1.html growth-schoolv2.html archive/
Move-Item 'growth-schoolv1 - 副本.html' archive/     # 未跟踪，用 Move
```

- **风险**：低（v1 无引用；v2 被 `archive/tasks/v2-vs-backend-gap.md` 提到一次，需改一行）
- **需同步**：`README.md` 目录结构树

### 阶段 3：文档归位到 `docs/`

```powershell
New-Item -ItemType Directory -Force -Path docs
git mv backend-handoff.md docs/
git mv 蛋蛋世界-PRD-v2.0.md docs/PRD-蛋蛋世界-v2.0.md
git mv growth-school-task-flows.md docs/
git mv TODO/迁移计划.md docs/
git mv TODO/email-quota.md docs/
git mv tasks docs/tasks
git mv TODO/TODO.md docs/TODO.md      # 或与 tasks/todo.md 合并后再定
```

- **风险**：中 —— 需修正 **13 处引用**（上表 1.3）
- ⚠️ **与协作者分支冲突**：他们在 `tasks/` 新增了 6 个文件，且其文档可能引用这些路径。
  **建议：合并双方确认后再单独做一个 PR 执行阶段 3。**
- 另需一并处理：`tasks/todo.md`(22KB) 与 `TODO/TODO.md` 去重合并

### 阶段 4（可选，后续）：测试目录统一命名

把 `tests/`（前端 Node 回归）与 `backend/src/test/`（Java 单测）在 README 里明确区分，
