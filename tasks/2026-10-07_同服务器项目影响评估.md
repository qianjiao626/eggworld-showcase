## 一、结论（先说最关键的）

**本次上线对同服务器其它项目是「零共享配置变更」**：

| 共享面 | 本次是否改动 | 结论 |
|---|---|---|
| **nginx 配置**（`/dd`、`/dd/blind-box`、`/MKJ`、`/xs` 与蛋蛋世界共用同一份 conf） | **不改** | 原本要改的两处（证明图请求体上限、限流真实 IP）已改用**不动 nginx** 的方案：证明图在浏览器侧压到 2 MB 内、限流改在应用侧读 `X-Real-IP` |
| **MySQL 实例** | 只跑 4 个脚本，全部限定在 `eggworld` 库 | 不碰其它库；脚本无 `USE`、无 `DROP`/`TRUNCATE`、无跨库写入 |
| **systemd 服务** | 只 `restart eggworld` | `/dd`（3310）、`/xs`（Node 3000）不受影响 |
| **端口 / 证书 / 静态目录** | 不新增端口、不动证书、不动 `/var/www/**` | 其它项目目录一个字节都不改 |
| **磁盘** | jar 35MB + 前端 ~1MB + 上传（压缩后 ≤1.8MB/张） | 增量很小；备份前先看余量 |

⚠️ 前提：**上线过程严格按下面「禁止事项」执行** —— 一旦有人顺手改 nginx（哪怕只是加一个 `location`），共享面就从「零」变成「五站同险」。

## 二、服务器上到底还住着谁（来自仓库 nginx 副本）

同一份 nginx 配置（`server_name dsxnb.com` / `www.dsxnb.com`）下：

| 路径 | 项目 | 后端/静态 |
|---|---|---|
| `/`、`/api/` | **蛋蛋世界（本次上线对象）** | 静态 `/home/xiaos/eggworld/xs` + `127.0.0.1:8090` |
| `/api/auth/` | 蛋蛋世界认证（另带 nginx 限流 `zone=eggworld_auth rate=1r/s burst=5`） | `127.0.0.1:8090` |
| `/dd/`、`/dd/api/`、`/dd/health` | **另一套应用** | `127.0.0.1:3310` + `/var/www/dd` |
| `/dd/blind-box/` | 该应用的盲盒静态页 | `alias /var/www/dd/blind-box/` |
| `/MKJ/` | **又一套静态站** | `root /var/www` |
| `/xs/` | **Node 应用**（`localhost:3000`）——名字和蛋蛋的 `xs/` 目录一样，但**是另一个项目**，别混 | `localhost:3000` |

`server` 级共享设置（本次都不动）：`client_max_body_size 2m`、静态后缀 `deny` 正则、gzip、`limit_req_status 429`、CSP 报告头、`proxy_*_timeout`。

## 三、逐项影响与安全做法

### 3.1 nginx（风险最高，本次改动为零）
- **本次动作**：无。证明图改由浏览器压缩（长边 ≤1920、≤1.8MB），不再需要放宽 `client_max_body_size`；限流真实 IP 改由应用读 `X-Real-IP`（nginx 早已在 `/api/` 用 `$remote_addr` 覆写该头），也不需要 `real_ip` 指令。
- **若将来确需放宽（例如要保留 3MB 以上原图）**，安全做法：
  1. 先备份：`cp /etc/nginx/conf.d/dsxnb.conf /home/xiaos/eggworld/backup/2026-10-07-nginx/dsxnb.conf.bak`（本地备份，**不要**在服务器上原地改后不备份）；
  2. 只**新增**一个 `location`，不修改现有 `location /dd/`、`/MKJ/`、`/xs/`；
  3. `nginx -t` 必须通过再 `systemctl reload nginx`（reload 不断连接、不重启别的项目）；
  4. **绝不要**在 `http {}` 块里加 `set_real_ip_from` / `real_ip_header` —— 那会改掉 `/dd`、`/MKJ`、`/xs` 看到的来源地址与日志。
- **禁止**：把仓库里的 `backend/deploy/*.conf` 直接覆盖线上（线上曾经与仓库漂移）；`nginx-xs-location.conf` 是**未部署**的历史片段，不能当线上现状。

### 3.2 MySQL（同一个实例，四个脚本）
- 只会执行：`migrate-announcements.sql`、`migrate-gossip-reports.sql`、`migrate-task-proof-image.sql`、`migrate-chatroom-channels.sql`。
- 全部是 `CREATE TABLE IF NOT EXISTS` + 条件 `ALTER`（加列/加索引）+ 一条 `UPDATE`（`chat_conversations` 归档官方频道）；**无 `DROP` / `TRUNCATE` / `DELETE`**，脚本内不写 `USE`，因此只会命中 `eggworld` 库。
- **不对其它库造成写影响**；读影响仅限 `information_schema` 探测（只读、无锁）。
- **备份命令建议加两个参数**，避免长时间持有表锁影响同实例上的其它库：
  ```bash
  mysqldump --single-transaction --quick -u eggworld -p eggworld > ~/eggworld/backup/db/eggworld_$(date +%Y%m%d_%H%M%S).sql
  chmod 600 ~/eggworld/backup/db/*.sql && ls -l ~/eggworld/backup/db/ | tail -3 && head -1 <本次 dump>
  ```
- **上线前实测确认（3 条只读命令）**：
  ```bash
  mysql -u eggworld -p -e "SELECT DATABASE(); SHOW GRANTS FOR CURRENT_USER();"   # 确认账号只对 eggworld 库有权限、不会误伤别的库
  mysql -u eggworld -p -e "SHOW DATABASES;"                                      # 看这台实例上还有哪些库（评估备份与磁盘）
  df -h ~ && du -sh ~/eggworld                                                # 余量与现有占用
  ```

### 3.3 systemd / 进程与端口
- `eggworld.service` 有强隔离：`User=xiaos`、`ProtectSystem=strict`、`ProtectHome=read-only`、`ReadWritePaths=/home/xiaos/eggworld`、`NoNewPrivileges`、`PrivateTmp`。**我们的进程连 `/var/www/**` 都写不了**，物理上不会碰到 `/dd`、`/MKJ` 的静态文件。
- `restart eggworld` 的影响范围：只有 `dsxnb.com/` 与 `/api/**` 短暂 502（几秒），`/dd`、`/MKJ`、`/xs` **不受影响**。
- 端口：本批不新增监听端口（仍只用 8090），与 `/dd`(3310)、`/xs`(3000) 无冲突。
- `Restart=always` + `RestartSec=5`：若 jar 启动失败会重启循环 —— 这只影响我们自己（表现为站点 502），但**会刷 journald**，所以启动失败要立刻看日志而不是放着不管。

### 3.4 磁盘与日志（共享资源，唯一可能「慢慢影响别人」的地方）
- 本批增量：`eggworld.jar` ≈35MB（覆盖旧文件，净增≈0）、前端 12 个 JS/CSS + `assets/pet-cat/**`（0.27MB）、索引 105 张 PNG 已在其中。
- 上传目录 `uploads/task-proof/`：**压缩后 ≤1.8MB/张**（压缩前手机照片 3–8MB），磁盘增速比不压缩小一个数量级；仍无自动清理，建议纳入观察。
- 库备份：`~/eggworld/backup/db/` 会多一份 dump；**上线前先看 `df -h ~`**，余量 <1GB 就先清理旧备份再上线。
- 日志：本批新增的日志是 `[MODULE_GATE]`（每个模块≤1 条/分钟）与 `[PURGE] 表不存在`（每次注销 1 条），量极小；另外把「缺表→500」的噪声消掉了。顺手看一眼 `journalctl --disk-usage`，必要时 `journalctl --vacuum-size=200M`。

### 3.5 部署文件落点（确认不会踩到别人的目录）
本次只写这几个位置，**全部在 `/home/xiaos/eggworld/` 内**：
`eggworld.jar`、`xs/index.html`、`xs/js/{12 个}`、`xs/assets/pet-cat/**`、`sql/*.sql`（随包留档）、`uploads/task-proof/`（新建）。

**与本批无关、不要碰**：`/var/www/MKJ/**`、`/var/www/dd/**`、`/home/xiaos/eggworld/backup/init.sql.READONLY-禁止执行`、`/etc/nginx/**`（本次无改动）、Node 应用目录、其它库。

### 3.6 与「蛋蛋世界自己」的共享点（提醒，不属于别的项目）
- `index.html` 是 `no-cache`，`/js/*` 是 7 天缓存 → 本批靠 `?v=YYYYMMDD` 升版本，用户不会「新 HTML + 旧 JS」。
- `/xs/` 这个路径属于 Node 项目，**我们前端目录也叫 `xs`**（`/home/xiaos/eggworld/xs/`），做运维命令时别把两者搞混（上传目标是 `/home/xiaos/eggworld/xs/`，不是 `/xs/`）。

## 六、禁止事项（违反任何一条，「零影响」结论立刻失效）

1. 不直接覆盖线上 nginx 配置；不在 `http {}` 块加 `real_ip_*`；不改现有 `location /dd/`、`/MKJ/`、`/xs/`。
2. 不执行 `init.sql`（含 19 条 `DROP TABLE`）、不执行三模块脚本、不 `DROP`/`TRUNCATE` 任何表。
3. 不用 `sudo` 建备份目录/拷文件（属主变 root 会让 `xiaos` 读不到 = 假回滚点）。
4. 不动 `/var/www/**`、Node 项目目录与其它数据库。
5. 不通过改数据库或配置来「回滚」；数据库只靠发布前的 dump。
6. 不做与本批无关的清理（旧备份、其它项目日志、`archive/`）——清理单独一次、单独授权。
