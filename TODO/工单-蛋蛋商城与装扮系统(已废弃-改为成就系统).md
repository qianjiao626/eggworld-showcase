## 一、背景与目标

### 1.1 要解决的根本问题

经全量核查 `point_logs` 的 21 处资金变动调用点，蛋蛋币存在**结构性通胀**：

| 方向 | 条目 |
|------|------|
| **发行（5 条）** | 注册 +100 · 签到 +5/天 · 吐槽 +10×2 · 邀请 +20 · 官方奖励任务 |
| **真实回收（仅 1 条）** | 组队未达标扣 20%（量极小） |
| 伪回收 | `freeze` / `spend` / `gossip_freeze` —— 均会退回或仅为用户间转移，不减少总量 |

**后果**：币持续贬值 → 悬赏失去吸引力 → 富豪榜失效 → 「完成任务赚币」的激励链条松动。

### 1.2 目标

| # | 目标 | 衡量口径 |
|---|------|---------|
| G1 | 建立消耗出口，抑制通胀 | 上线后月度回收量 ≥ 月度发行量的 40% |
| G2 | 给用户「攒币理由」，提升任务完成动机 | 有装扮用户月均完成任务数 ≥ 无装扮用户的 1.5 倍 |
| G3 | 形成社交展示闭环，提升留存 | 装扮穿戴率 ≥ 活跃用户的 30% |

### 1.3 已确认口径

| # | 决策项 | 结论 |
|---|--------|------|
| 1 | 生效范围 | **全站所有出现昵称/头像的位置** |
| 2 | 商品时效 | **混合**：N/R/SR 永久；SSR/UR 限时 30 天（可续期） |
| 3 | 技术路线 | **纯 CSS + SVG 动效**，零素材文件、无需上传 `/xs/assets/` |
| 4 | 效果强度 | 放射光束 + 三层同心环 + 环绕星轨 + 冲击波 + 能量核心 |
| 5 | 槽位数量 | **7 个**（含新增的服装与披风） |

## 二、设计定稿

### 2.1 七槽位与九层渲染结构

装扮拆为 **7 个可独立穿戴的槽位**，按 **9 层 z-index** 渲染：

| z-index | 层 | 元素 | 说明 |
|---------|----|------|------|
| 0 | 暗场 / 光束 | `.fx-field` / `.fx-rays` | `.fx-field` 为可选，见 2.6 |
| 1 | 能量核心 | `.fx-core` | 头像背后脉冲光晕 |
| 2 | 冲击波 | `.fx-wave` ×2 | 向外扩散并淡出 |
| 3 | **披风** | `.fx-cloak` | **位于立绘下方，向外展开** |
| 4 | 光环 / 星轨 | `.r-ring` ×3、`.r-orbit` ×2 | 旋转环与环绕星 |
| 5 | 立绘 | `.egg-img` | 角色本体 |
| 6 | **服装** | `.fx-outfit` | **位于立绘上方，落在身体下部** |
| 7 | 边框 | `.fx-frame` | 头像外圈 |
| 8 | 挂件 | `.fx-charm` | 右下角角标 |

**各槽位尺寸（相对头像）**：

| 槽位 | 定位 | 尺寸 |
|------|------|------|
| `.fx-field` | `inset:-32px` | 圆形 |
| `.fx-rays` | `inset:-64px` | 圆形 |
| `.fx-cloak` | `inset:-46px` | `background-size:100% 100%` |
| `.r-ring` | `inset:-10px`（r2: -22px，r3: -34px） | 圆形 |
| `.r-orbit` | `inset:-42px` | 圆形 |
| `.fx-outfit` | `inset:0` | `background-position:center 74%`，`background-size:42% auto` |
| `.fx-charm` | `right/bottom:-6px` | `44×44px` |

### 2.2 稀有度 → 动画强度

| 稀有度 | 效果组成 | 时效 |
|--------|---------|------|
| **N** | 静态描边 / 静态剪影 | 永久 |
| **R** | 单环旋转 / 单层形态 | 永久 |
| **SR** | 双环反向 / 多层形态 + 闪烁 | 永久 |
| **SSR** | 三层环 + 光束 + 冲击波 + 粒子 | 30 天 |
| **UR** | 三层环 + 光束 + 双冲击波 + 八星环绕 + 核心 | 30 天 |

### 2.3 关于「衣服」的实现原理（重要）

蛋蛋立绘本身已画好服装、帽子与配饰，直接叠加会导致穿帮。本方案用**身前 / 身后双层**绕开该问题：

| 层 | 槽位 | 原理 | 为何不穿帮 |
|----|------|------|-----------|
| **身后**（z-index 3） | **披风 cloak** | 位于立绘**下方**，从头像圆形背后向外展开 | 圆形外的部分是可见的，形成披风/翅膀剪影；**圆形内的部分被立绘遮住，完全不存在错位问题** |
| **身前**（z-index 6） | **服装 outfit** | 位于立绘**上方**，仅占头像下部约 42% 宽的一小块 | 该区域是蛋蛋的身体（纯色衣服区、无复杂细节），叠加领结/胸甲/徽章非常自然 |

> 若产品后续要求"真正替换立绘的换装"，则需为 7 个角色各重绘多套立绘，属独立美术排期，**不在本工单范围**。

### 2.6 ⚠️ 浅色主题适配（必须处理）

**设计预览是深色底，主站是浅色底（米色/奶油色）。** 发光效果在浅色背景上会减弱。处理方式：

1. **效果本身不改** —— 彩色环、披风、服装、粒子在浅色底上依然清晰可辨，只是少了霓虹光晕感
2. **`.fx-field`（可选暗场层）** 建议只在**大尺寸场景**启用：

```css
/* 可选：给头像加一圈渐隐暗场，让光束/星轨/冲击波获得应有的对比度。
   建议只在「我的信息页」与「用户名片弹窗」启用；
   列表页（榜单/任务卡/八卦）不要启用，避免大量深色圆盘破坏浅色版面。
   注：披风与服装本身是实色/渐变，浅色底上无需暗场即清晰。 */
.fx-field{position:absolute;inset:-32px;border-radius:50%;z-index:0;pointer-events:none;
  background:radial-gradient(circle,rgba(11,16,32,.9) 0%,rgba(11,16,32,.8) 40%,rgba(11,16,32,.3) 62%,rgba(11,16,32,0) 78%)}
```

**侧边栏本来就是深色底**（紫蓝渐变），侧边栏头像无需 `.fx-field`，效果自然呈现最佳观感。

## 三、数据模型

### 3.1 新增 3 张表

**文件**：`backend/sql/migrate-shop.sql`（新建增量脚本，**同时并入 `init.sql`**）

```sql
-- ============================================================
-- 蛋蛋商城 + 装扮系统（v2.5）
-- 执行: mysql -u root -p eggworld < migrate-shop.sql
-- ============================================================

-- 1. 商品定义表
CREATE TABLE IF NOT EXISTS shop_items (
  id            BIGINT PRIMARY KEY AUTO_INCREMENT,
  item_key      VARCHAR(64)  NOT NULL COMMENT '唯一标识，同时作为前端 CSS 类名，如 a-cosmos',
  name          VARCHAR(50)  NOT NULL COMMENT '商品名',
  slot          ENUM('aura','cloak','outfit','frame','charm','title','skin') NOT NULL COMMENT '槽位（7 选 1）',
  rarity        ENUM('N','R','SR','SSR','UR') NOT NULL DEFAULT 'N',
  price         INT          NOT NULL COMMENT '售价（蛋蛋币）',
  duration_days INT          NULL COMMENT '有效天数；NULL=永久',
  stock         INT          NULL COMMENT '库存；NULL=不限量',
  sold          INT          NOT NULL DEFAULT 0,
  sort_order    INT          NOT NULL DEFAULT 0,
  enabled       TINYINT      NOT NULL DEFAULT 1 COMMENT '1上架 0下架',
  description   VARCHAR(200) NULL,
  created_at    DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at    DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  UNIQUE KEY uk_item_key (item_key),
  KEY idx_slot_enabled (slot, enabled, sort_order)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='商城商品定义';

-- 2. 用户持有表
CREATE TABLE IF NOT EXISTS user_items (
  id          BIGINT PRIMARY KEY AUTO_INCREMENT,
  user_id     BIGINT NOT NULL,
  item_id     BIGINT NOT NULL,
  acquired_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  expire_at   DATETIME NULL COMMENT '过期时间；NULL=永久持有',
  UNIQUE KEY uk_user_item (user_id, item_id),
  KEY idx_user_expire (user_id, expire_at),
  CONSTRAINT fk_ui_user FOREIGN KEY (user_id) REFERENCES users(id),
  CONSTRAINT fk_ui_item FOREIGN KEY (item_id) REFERENCES shop_items(id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='用户已购商品（含限时过期时间）';

-- 3. 穿戴状态表（一用户一行，7 个槽位）
CREATE TABLE IF NOT EXISTS user_equip (
  user_id        BIGINT PRIMARY KEY,
  aura_item_id   BIGINT NULL,
  cloak_item_id  BIGINT NULL,
  outfit_item_id BIGINT NULL,
  frame_item_id  BIGINT NULL,
  charm_item_id  BIGINT NULL,
  title_item_id  BIGINT NULL,
  skin_item_id   BIGINT NULL,
  updated_at     DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  CONSTRAINT fk_ue_user FOREIGN KEY (user_id) REFERENCES users(id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='用户当前穿戴的装扮（7 槽位）';
```

**要点**：
- `point_logs.type` 为 `VARCHAR(50)` 非 ENUM，**无需 DDL 变更**，购买复用 `spend` 类型
- `uk_user_item` 同时支撑两种场景：永久商品防重复购买；限时商品重复购买时**累加 `expire_at`** 实现续期
- **用户注销须清理这三张表** → 需同步修改 `UserPurgeMapper`

### 4.3 `DecoService` —— 全站装扮批量加载（性能关键）

全站生效意味着**每个列表接口都要返回装扮数据**，必须避免 N+1。

```java
/** 批量加载多个用户的装扮（单次 JOIN，禁止在循环内逐用户查询） */
public Map<Long, DecoVO> loadDecos(Collection<Long> userIds) {
    if (userIds == null || userIds.isEmpty()) return Collections.emptyMap();
    return userEquipMapper.selectDecosByUserIds(userIds);
}
```

`DecoVO`（**7 个字段**）：
```java
public class DecoVO {           // 全为 null 时不返回该用户，前端按默认样式渲染
    private String aura;        // item_key
    private String cloak;
    private String outfit;
    private String frame;
    private String charm;
    private String title;
    private String skin;
}
```

`UserEquipMapper` 单条 JOIN（一次查完所有用户的所有槽位）：
```sql
SELECT ue.user_id,
       a.item_key AS aura,  cl.item_key AS cloak, of2.item_key AS outfit,
       f.item_key AS frame, c.item_key  AS charm, t.item_key   AS title,
       s.item_key AS skin
FROM user_equip ue
LEFT JOIN shop_items a   ON a.id   = ue.aura_item_id
LEFT JOIN shop_items cl  ON cl.id  = ue.cloak_item_id
LEFT JOIN shop_items of2 ON of2.id = ue.outfit_item_id
LEFT JOIN shop_items f   ON f.id   = ue.frame_item_id
LEFT JOIN shop_items c   ON c.id   = ue.charm_item_id
LEFT JOIN shop_items t   ON t.id   = ue.title_item_id
LEFT JOIN shop_items s   ON s.id   = ue.skin_item_id
WHERE ue.user_id IN (...)
```

> ⚠️ `of` 是 SQL 保留字风险较低但为避免歧义，别名统一用 `of2`。

**过期装扮不得生效**：JOIN 时关联 `user_items` 校验 `expire_at IS NULL OR expire_at > NOW()`，避免"过期了但还穿着"。

**接入点清单（须逐个改造，返回体加 `deco` 字段）**：

| 接口 | VO | 涉及用户 |

### 4.4 `ShopService.buy()` —— 资金安全（硬约束，不得变通）

> ⚠️ 本项目刚完成资金安全审计。购买流程必须严格按以下实现。

```java
@Transactional
public void buy(Long userId, Long itemId) {
    ShopItem item = shopItemMapper.selectById(itemId);
    if (item == null || item.getEnabled() != 1) {
        throw new BusinessException("商品不存在或已下架");
    }

    // 1. 库存：条件更新抢占，防超卖
    if (item.getStock() != null) {
        if (shopItemMapper.decrStockIfAvailable(itemId) != 1) {
            throw new BusinessException("商品已售罄");
        }
    }

    // 2. 扣款：唯一出口必须走 PointService（自带事务 + 行锁 + 流水）
    pointService.changeBalance(userId, -item.getPrice(), "spend",
            "购买装扮：" + item.getName(), null);

    // 3. 持有：永久防重，限时续期
    UserItem owned = userItemMapper.selectByUserAndItem(userId, itemId);
    if (owned == null) {
        UserItem ui = new UserItem();
        ui.setUserId(userId);
        ui.setItemId(itemId);
        if (item.getDurationDays() != null) {
            ui.setExpireAt(LocalDateTime.now().plusDays(item.getDurationDays()));
        }
        userItemMapper.insert(ui);          // 唯一键兜底防并发重复
    } else {
        if (item.getDurationDays() == null) {
            throw new BusinessException("你已永久拥有该装扮");
        }
        // 续期：从「当前剩余到期时间」与「现在」中较晚者起算
        LocalDateTime base = owned.getExpireAt() != null
                && owned.getExpireAt().isAfter(LocalDateTime.now())
                ? owned.getExpireAt() : LocalDateTime.now();
        owned.setExpireAt(base.plusDays(item.getDurationDays()));
        userItemMapper.updateById(owned);
    }

    // 4. 售出计数：原子自增
    shopItemMapper.incrSold(itemId);

    notificationService.notify(userId, "成功购买装扮「" + item.getName() + "」", "shop");
}
```

**必须满足的约束**：
1. **扣款只能走 `PointService.changeBalance`** —— 不得直接改 `users.points`
2. **库存用条件更新**：`UPDATE shop_items SET stock = stock - 1 WHERE id = ? AND stock > 0`
3. **`sold` 用原子自增**：`UPDATE shop_items SET sold = sold + 1 WHERE id = ?`
4. **唯一键兜底**：`uk_user_item` 防并发重复购买，捕获 `DuplicateKeyException` 转业务提示
5. **价格从数据库读取** —— 严禁信任前端传入的价格

### 4.5 穿戴接口的归属校验（防越权）

`PUT /api/users/me/equip` **必须校验四项**，缺一不可：

### 5.3 `js/deco.js` 完整代码

```javascript
/* ============================================================
 * 蛋蛋世界 · 装扮渲染助手
 * 唯一入口：所有出现昵称/头像的地方都必须调用 applyDeco，
 * 禁止各页面自行拼接装饰 HTML（避免 XSS 面扩散）。
 * ============================================================ */

/* item_key 白名单正则：前缀 a-/cl-/of-/f-/ch-/sk- 与 title-，须与后端
   DECO_KEY_WHITELIST 及 deco.css 类名三方一致 */
var DECO_KEY_RE = /^(?:(?:a|cl|of|f|ch|sk)-[a-z]{2,14}|title-[a-z]{2,14})$/;
var DECO_SLOTS = ['aura', 'cloak', 'outfit', 'frame', 'charm', 'title', 'skin'];

/* 生成装扮容器内部结构。light=true 时跳过高开销节点（光束/冲击波/星轨） */
function decoMarkup(imgSrc, light) {
  var h = '<span class="fx-core"></span>';
  if (!light) {
    h += '<span class="fx-rays"></span>'
       + '<span class="fx-wave w1"></span><span class="fx-wave w2"></span>'
       + '<span class="r-orbit o1"><i></i><i></i><i></i><i></i></span>'
       + '<span class="r-orbit o2"><i></i><i></i><i></i><i></i></span>';
  }
  h += '<span class="fx-cloak"></span>'
     + '<span class="r-ring r1"></span><span class="r-ring r2"></span><span class="r-ring r3"></span>'
     + '<img class="egg-img" src="' + encodeURI(imgSrc) + '" alt="">'
     + '<span class="fx-outfit"></span><span class="fx-frame"></span><span class="fx-charm"></span>';
  return h;
}

/* 把装扮类名挂到容器上。安全要求：
   只用 classList.add + 白名单正则，禁止 innerHTML 拼接 deco 字段值 */
function applyDeco(wrapEl, deco, light) {
  if (!wrapEl) return;
  Array.prototype.slice.call(wrapEl.classList).forEach(function (c) {
    if (DECO_KEY_RE.test(c)) wrapEl.classList.remove(c);
  });
  wrapEl.classList.add('egg-deco');
  if (light) wrapEl.classList.add('deco-light');
  if (!deco) return;

  DECO_SLOTS.forEach(function (slot) {
    var k = deco[slot];
    if (k && DECO_KEY_RE.test(k)) wrapEl.classList.add(k);
  });

  var host = wrapEl.parentNode;
  var nameEl = host && host.querySelector('.deco-title');
  if (nameEl) {
    nameEl.classList.remove('title-plain', 'title-gold', 'title-neon', 'title-flame', 'title-holo');
    nameEl.classList.add(deco.title && DECO_KEY_RE.test(deco.title) ? deco.title : 'title-plain');
  }
}

/* 用户级特效降级开关（「我的信息」页勾选，存 localStorage） */
var DECO_FX_KEY = 'egg_deco_fx_off';
function decoFxEnabled() {
  try { return localStorage.getItem(DECO_FX_KEY) !== '1'; } catch (e) { return true; }
}
function setDecoFx(on) {
  try { localStorage.setItem(DECO_FX_KEY, on ? '0' : '1'); } catch (e) {}
  document.body.classList.toggle('fx-off', !on);
}
document.addEventListener('DOMContentLoaded', function () {
  if (!decoFxEnabled()) document.body.classList.add('fx-off');
});
```

## 十、注意事项汇总

1. **扣款只能走 `PointService.changeBalance`** —— 项目资金纪律，不得直接改 `users.points`
2. **库存与计数必须条件更新 / 原子自增** —— 并发经典陷阱
3. **`DecoService.loadDecos` 必须批量单次 JOIN** —— 全站生效的前提，禁止循环内查库
4. **装扮渲染只用 `classList.add` + 白名单校验** —— 不得引入新的 XSS 面
5. **`item_key` 三方一致** —— 后端白名单 / 前端 `DECO_KEY_RE` / `deco.css` 类名
6. **9 层 z-index 不可错序** —— 披风（3）必须在立绘（5）**下方**，服装（6）必须在立绘**上方**
7. **CSS 提取时不要带入预览的深色主题变量** —— 生产沿用主站浅色体系
8. **`growth-schoolv3.html` 是协作热点文件** —— 按 `COLLABORATION.md` 需与协作者错峰修改
9. **`assets/` 不需要新增任何文件** —— 本方案为零素材设计，这是刻意的
