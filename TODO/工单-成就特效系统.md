## 一、背景与目标

### 1.1 方案变更说明

原方案为「蛋蛋币商城（购买装扮）」，**现改为「成就系统（做任务解锁装扮）」**。

| 维度 | 商城方案（已废弃） | 成就方案（本工单） |
|------|-----------------|-----------------|
| 获取方式 | 花蛋蛋币购买 | 完成行为自动解锁 |
| 是否涉及货币 | 是（扣币、库存、超卖、续期） | **否**（完全不碰资金链路） |
| 复杂度 | 高（购买事务、库存并发、过期定时任务） | 低（解锁幂等即可） |
| 时效 | 混合永久 / 限时 | **全部永久**（奖励不应过期） |
| 产品效果 | 回收蛋蛋币 | 行为引导 + 留存 + 成就收集乐趣 |

**简化收益**：不需要改资金链路、不需要库存并发控制、不需要过期清理任务、不需要管理端定价。整体风险显著下降。

### 1.2 ⚠️ 必须知晓的连带影响

**去掉商城后，蛋蛋币的通胀问题重新变为无解。**

前期审计已确认：蛋蛋币有 **5 条发行来源**（注册 +100 / 签到 +5 / 吐槽 +10×2 / 邀请 +20 / 官方奖励），但**只有 1 个真实回收口**（组队未达标扣 20%）。商城原本是唯一的消耗出口。

本工单**不解决**该问题（成就系统不消耗货币）。建议后续单独设计方案，可选方向：

- 用蛋蛋币「重抽 / 刷新」某项成就的展示样式（消耗但非必需）
- 成就额外附加蛋蛋币奖励 → 只会加剧通胀，**不推荐**
- 专门的经济回收机制（另立工单）

> 本工单对此仅作登记，不在范围内实施。

### 1.3 目标

| # | 目标 | 衡量口径 |
|---|------|---------|
| G1 | 以成就驱动行为，提升任务完成与签到活跃 | 上线后月活用户的人均签到天数 +30% |
| G2 | 给新用户即时正反馈，降低流失 | 新用户 7 日留存 +15% |
| G3 | 形成社交展示闭环 | 装扮穿戴率 ≥ 活跃用户的 40% |

### 1.4 已确认口径

| # | 决策项 | 结论 |
|---|--------|------|
| 1 | 获取方式 | **成就解锁**，不可购买 |
| 2 | 时效 | **全部永久**，无过期 |
| 3 | 生效范围 | **全站所有出现昵称/头像的位置** |
| 4 | 技术路线 | **纯 CSS + SVG 动效**（零素材，无需上传 `/xs/assets/`） |
| 5 | 槽位 | **7 个**：光环 / 披风 / 服装 / 边框 / 挂件 / 称号 / 皮肤 |
| 6 | 称号形态 | **名称 + 样式**（名称是文本，样式是视觉档位） |

### 2.5 ⚠️ 浅色主题适配

**效果库预览是深色底，主站是浅色底。** 彩色环、披风、服装、挂件在浅色底上依然清晰，但发光感减弱。

**请在实施前先打开 `TODO/成就页原型.html` 第一节「浅色底效果实测」** —— 该节已把 6 种组合渲染在浅色背景上，并对比了可选暗场层 `.fx-field` 的开启 / 关闭差异。

```css
/* 可选暗场层：给头像加一圈渐隐暗场，让光束/星轨/冲击波获得对比度。
   建议只在「我的信息页」与「用户名片弹窗」这类大尺寸场景启用；
   列表页不要启用，避免大量深色圆盘破坏浅色版面。 */
.fx-field{position:absolute;inset:-32px;border-radius:50%;z-index:0;pointer-events:none;
  background:radial-gradient(circle,rgba(11,16,32,.9) 0%,rgba(11,16,32,.8) 40%,rgba(11,16,32,.3) 62%,rgba(11,16,32,0) 78%)}
```

**侧边栏本身是深色底**（紫蓝渐变），侧边栏头像无需 `.fx-field`。

## 三、数据模型

### 3.1 新增 4 张表

**文件**：`backend/sql/migrate-achievement.sql`（新建增量脚本，**同时并入 `init.sql`**）

```sql
-- ============================================================
-- 成就特效系统（v2.5）
-- 执行: mysql -u root -p eggworld < migrate-achievement.sql
-- ============================================================

-- 1. 称号定义
CREATE TABLE IF NOT EXISTS titles (
  id          BIGINT PRIMARY KEY AUTO_INCREMENT,
  title_key   VARCHAR(48) NOT NULL COMMENT '如 t-steady',
  name        VARCHAR(20) NOT NULL COMMENT '称号文本，如「雷打不动」',
  style_class VARCHAR(32) NOT NULL COMMENT '样式：title-plain/title-gold/title-neon/title-flame/title-holo',
  rarity      ENUM('N','R','SR','SSR','UR') NOT NULL DEFAULT 'N',
  sort_order  INT NOT NULL DEFAULT 0,
  UNIQUE KEY uk_title_key (title_key)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='称号定义';

-- 2. 成就定义
CREATE TABLE IF NOT EXISTS achievements (
  id                 BIGINT PRIMARY KEY AUTO_INCREMENT,
  ach_key            VARCHAR(48)  NOT NULL COMMENT '如 ach_checkin_1',
  name               VARCHAR(40)  NOT NULL,
  category           VARCHAR(20)  NOT NULL COMMENT 'checkin/publish/complete/team/rating/gossip/invite/complaint/meta',
  description        VARCHAR(200) NOT NULL COMMENT '条件描述，前端展示',
  cond_type          VARCHAR(32)  NOT NULL COMMENT '判定类型',
  cond_value         INT          NOT NULL COMMENT '阈值',
  reward_effect_key  VARCHAR(64)  NULL COMMENT '奖励特效（deco 类名）',
  reward_effect_slot VARCHAR(16)  NULL COMMENT '特效槽位',
  reward_title_key   VARCHAR(48)  NULL COMMENT '奖励称号 key',
  sort_order         INT NOT NULL DEFAULT 0,
  enabled            TINYINT NOT NULL DEFAULT 1,
  UNIQUE KEY uk_ach_key (ach_key),
  KEY idx_cat_sort (category, sort_order)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='成就定义';

-- 3. 用户成就解锁记录
CREATE TABLE IF NOT EXISTS user_achievements (
  id          BIGINT PRIMARY KEY AUTO_INCREMENT,
  user_id     BIGINT NOT NULL,
  ach_id      BIGINT NOT NULL,
  unlocked_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  is_read     TINYINT  NOT NULL DEFAULT 0 COMMENT '是否已查看解锁弹窗',
  UNIQUE KEY uk_user_ach (user_id, ach_id),
  KEY idx_user_unread (user_id, is_read),
  CONSTRAINT fk_ua_user FOREIGN KEY (user_id) REFERENCES users(id),
  CONSTRAINT fk_ua_ach  FOREIGN KEY (ach_id)  REFERENCES achievements(id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='用户成就解锁记录';

-- 4. 用户当前穿戴（7 槽位，直接存 key）
CREATE TABLE IF NOT EXISTS user_equip (
  user_id    BIGINT PRIMARY KEY,
  aura_key   VARCHAR(64) NULL,
  cloak_key  VARCHAR(64) NULL,
  outfit_key VARCHAR(64) NULL,
  frame_key  VARCHAR(64) NULL,
  charm_key  VARCHAR(64) NULL,
  title_key  VARCHAR(48) NULL,
  skin_key   VARCHAR(64) NULL,
  updated_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  CONSTRAINT fk_ue_user FOREIGN KEY (user_id) REFERENCES users(id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='用户当前穿戴的装扮（7 槽位，存 key）';
```

**设计说明**：
- `user_equip` 直接存 **key 字符串**（不再存 item_id）—— 因为特效是**代码定义的静态资源**，没有对应的数据表，不需要外键
- 「用户已解锁哪些装扮」通过 `user_achievements JOIN achievements` 派生，**不额外冗余存储**
- **用户注销须清理 `user_achievements` 与 `user_equip`** → 需同步修改 `UserPurgeMapper`

### 4.3 `AchievementService` —— 解锁引擎（核心）

```java
/**
 * 评估某分类下的成就，解锁所有已达标但尚未解锁的成就。
 * 幂等：重复调用无副作用（依赖 uk_user_ach 唯一键）。
 *
 * @param category 只评估该分类，避免每次全量计算；传 null 表示全量（供每日任务使用）
 */
@Transactional
public void evaluate(Long userId, String category) {
    // 1. 取该用户在各 cond_type 上的当前进度（按需计算的 Map）
    Map<String, Integer> progress = computeProgress(userId, category);

    // 2. 查该分类下已启用的成就
    List<Achievement> list = achievementMapper.selectEnabled(category);

    for (Achievement a : list) {
        // 已解锁则跳过（也可直接用 INSERT IGNORE 兜底）
        if (userAchievementMapper.exists(userId, a.getId())) continue;

        int cur = progress.getOrDefault(a.getCondType(), 0);
        if (cur < a.getCondValue()) continue;

        // 3. 解锁
        UserAchievement ua = new UserAchievement();
        ua.setUserId(userId);
        ua.setAchId(a.getId());
        try {
            userAchievementMapper.insert(ua);
        } catch (DuplicateKeyException e) {
            continue;   // 并发下已被另一线程解锁
        }

        // 4. 通知（文案含奖励内容）
        notificationService.notify(userId, buildUnlockMessage(a), "achievement");
    }
}
```

**进度计算（`computeProgress`）按 `cond_type` 分派，全部为只读聚合查询**：

| cond_type | 计算方式 |
|-----------|---------|
| `checkin_total` | `SELECT COUNT(*) FROM daily_checkins WHERE user_id = ?` |
| `checkin_streak` | 取 `daily_checkins` 的 `check_date` 倒序，从今天（或昨天）向前数连续天数 |
| `publish_count` | `SELECT COUNT(*) FROM tasks WHERE publisher_id = ? AND deleted = 0` |
| `complete_count` | 作为认领者完成的认领数 + 作为发布者确认完成的任务数（口径见下） |
| `team_count` | `task_claims` JOIN `tasks`，`task_type='team' AND status='completed'`，按参与者计 |
| `rating_five_count` | `SELECT COUNT(*) FROM ratings WHERE ratee_id = ? AND score = 5 AND visible = 1 AND is_auto = 0` |
| `rating_quality` | 评价数 ≥ `cond_value` **且** 均分 ≥ 4.8（4.8 为硬编码阈值，写入注释） |
| `gossip_adopted_count` | `SELECT COUNT(*) FROM gossip_answers WHERE author_id = ? AND is_adopted = 1` |
| `invite_count` | `SELECT COUNT(*) FROM invite_records WHERE inviter_id = ? AND status = 'rewarded'` |
| `complaint_count` | `SELECT COUNT(*) FROM school_complaints WHERE user_id = ?` |
| `meta_category_count` | 已解锁成就覆盖的不同 `category` 数量 |
| `meta_ach_count` | `SELECT COUNT(*) FROM user_achievements WHERE user_id = ?` |
| `register_days` | `DATEDIFF(NOW(), users.created_at)` |

> **`complete_count` 口径必须写死并写进注释**：建议 = 「作为认领者、认领记录 `status='completed'` 的数量」＋「作为发布者、任务 `status='completed'` 的数量」。两者都算"完成了一个任务"，符合用户直觉。实施时请把该口径写入代码注释，避免后续争议。

> **`checkin_streak` 实现提示**：不要用 SQL 硬算，取最近 120 天的 `check_date` 列表到内存里遍历更简单可靠。

### 5.3 `js/deco.js` 完整代码

```javascript
/* ============================================================
 * 蛋蛋世界 · 装扮渲染助手
 * 唯一入口：所有出现昵称/头像的地方都必须调用 applyDeco，
 * 禁止各页面自行拼接装饰 HTML（避免 XSS 面扩散）。
 * ============================================================ */

/* key 白名单正则：前缀 a-/cl-/of-/f-/ch-/sk- 与 t-，须与后端白名单及 deco.css 三方一致 */
var DECO_KEY_RE = /^(?:(?:a|cl|of|f|ch|sk)-[a-z]{2,14}|t-[a-z]{2,14})$/;
var DECO_EFF_SLOTS = ['aura', 'cloak', 'outfit', 'frame', 'charm', 'skin'];

/* 生成装扮容器内部结构。light=true 时跳过高开销节点（光束/冲击波/星轨） */
function decoMarkup(imgSrc, light) {
  var h = '<span class="fx-core"></span>';
  if (!light) {
    h += '<span class="fx-rays"></span>'
       + '<span class="fx-wave w1"></span><span class="fx-wave w2"></span>'
       + '<span class="r-orbit o1"><i></i><i></i><i></i><i></i></span>'
       + '<span class="r-orbit o2"><i></i><i></i><i></i><i></i></span>';
  }
  h += '<span class="fx-cloak"></span>'
     + '<span class="r-ring r1"></span><span class="r-ring r2"></span><span class="r-ring r3"></span>'
     + '<img class="egg-img" src="' + encodeURI(imgSrc) + '" alt="">'
     + '<span class="fx-outfit"></span><span class="fx-frame"></span><span class="fx-charm"></span>';
  return h;
}

/* 把装扮 key 挂到容器上。安全要求：
   只用 classList.add + 白名单正则，禁止 innerHTML 拼接 deco 字段值 */
function applyDeco(wrapEl, deco, light) {
  if (!wrapEl) return;
  Array.prototype.slice.call(wrapEl.classList).forEach(function (c) {
    if (DECO_KEY_RE.test(c)) wrapEl.classList.remove(c);
  });
  wrapEl.classList.add('egg-deco');
  if (light) wrapEl.classList.add('deco-light');
  if (!deco) return;

  DECO_EFF_SLOTS.forEach(function (slot) {
    var k = deco[slot];
    if (k && DECO_KEY_RE.test(k)) wrapEl.classList.add(k);
  });

  var host = wrapEl.parentNode;
  var nameEl = host && host.querySelector('.deco-title');
  if (nameEl) {
    nameEl.classList.remove('title-plain','title-gold','title-neon','title-flame','title-holo');
    var st = deco.titleStyle;
    nameEl.classList.add(st && /^title-[a-z]+$/.test(st) ? st : 'title-plain');
  }
}

/* 用户级特效降级开关（「我的信息」页勾选，存 localStorage） */
var DECO_FX_KEY = 'egg_deco_fx_off';
function decoFxEnabled() {
  try { return localStorage.getItem(DECO_FX_KEY) !== '1'; } catch (e) { return true; }
}
function setDecoFx(on) {
  try { localStorage.setItem(DECO_FX_KEY, on ? '0' : '1'); } catch (e) {}
  document.body.classList.toggle('fx-off', !on);
}
document.addEventListener('DOMContentLoaded', function () {
  if (!decoFxEnabled()) document.body.classList.add('fx-off');
});
```

### 5.6 性能策略

| 措施 | 说明 |

## 九、注意事项汇总

1. **解锁必须幂等** —— 依赖 `uk_user_ach` 唯一键 + 捕获 `DuplicateKeyException`，重复触发不能重复解锁
2. **成就评估绝不能影响主流程** —— 签到、发布、完成任务是核心链路，评估异常必须被吞掉
3. **触发点要放在事务提交后** —— 建议 `afterCommit` 回调
4. **`DecoService.loadDecos` 必须批量单次查询** —— 全站生效的前提
5. **`complete_count` 口径要写进代码注释** —— 避免后续争议
6. **穿戴必须校验「已解锁」** —— 这是本系统唯一的越权风险点
7. **装扮渲染只用 `classList.add` + 白名单** —— 不得引入新的 XSS 面
8. **9 层 z-index 不可错序** —— 披风(3) 在立绘(5) 下方，服装(6) 在上方
9. **CSS 提取时不要带入预览的深色主题变量** —— 生产沿用主站浅色体系
10. **`growth-schoolv3.html` 是协作热点文件** —— 按 `COLLABORATION.md` 需与协作者错峰修改
11. **`assets/` 不需要新增任何文件** —— 零素材设计
