## 一、本次范围

「任务绑定群聊」上线后，后端流程已经变了（教学/组队审核通过自动建群、认领即入队、完成即归档），但**前端还有大量指向「互加微信/QQ、手动配对」的入口与文案**。本次把前端交互整体收口到「任务群」这条主线，做减法与替换：

1. **发布任务（§1）**：教学/组队隐藏「联系方式」输入框（不再收集站外联系方式），换成一条「沟通方式升级」提示卡；「最多可选人数」下补组队冻资提示（确认发布即冻结 10 币，入队搭子各冻 10 币）。**求助型保留联系方式**（没有任务群，选中后只能靠它联系）。
2. **任务详情与认领（§2）**：教学/组队的入口按钮改为「立即认领（直接进群）」；认领确认弹窗对教学/组队隐藏联系方式输入块，把「资金 + 进群」做成居中强调（教学「支付 X 蛋蛋币，并立即加入教学专属群聊」／组队「冻结 X 蛋蛋币，并立即加入项目协作群聊」）；认领成功后不再只弹 Toast，而是弹「认领成功！已为你加入群聊」+ **「👉 立即前往聊天室」**直达按钮。
3. **我的任务卡片（§3）**：把原来的「💬 进入群聊」文字链**升级为操作区最左侧的主按钮**（紫色渐变），有未读消息时右上角挂小红点；卡片说明改为「已建立专属群聊，请在群内同步进度（沟通请到任务群）」。
4. **历史兼容与人员管理（§4）**：新版教学/组队（认领即入队、满员自动关）不再给发布者「学员名单/搭子名单」按钮，统一走任务群；只有**改版前遗留的待配对报名**才保留该入口，并在弹窗顶部显示黄底「旧版报名记录」警告。组队「查看队友/我的搭子」在有任务群时**直接进群**（成员看群侧栏），不再重复弹名单。
5. **收尾与归档预期（§5）**：「确认完成」弹窗新增归档预告（全部确认后群聊转只读归档）；聊天室在会话 `readOnly=1` 时**隐藏输入区**，换成「✅ 任务已完成，当前群聊已归档，仅供查看历史记录。」

要解决的用户问题：站外联系方式（微信/QQ）暴露与断链；以及新流程上线后前端仍在诱导「加微信、等挑选」，与后端实际行为不一致。

**本批不改任何接口与请求参数**：认领成功弹窗的会话 ID 取自任务卡片上的 `conversationId`（后端审核通过时回写），跳转复用既有的 `enterTaskChat()` → `window.chatroomOpenById()`。

## 七、备注 / 已知边界

1. **本批取代 `2026-09-26_认领弹窗按任务类型区分.md`**（同一 PR 内的 `4fb5c15`）：该批把教学/组队入口按钮写成「加入任务 / 加入队伍」，本批已按最终口径改为「立即认领（直接进群）」，弹窗说明也从「⚠️ 确认后立即占名额…」改为居中的「支付/冻结 X 币 + 立即进群」。**上线以本文档为准**；那份文档已加「被本批取代」抬头，不再单独作为上线依据。
2. **🔴 名单按钮的判据是「还有没有待配对报名」，不是「有没有 conversation_id」**（刻意的偏离）：设计原话是按 `conversation_id` 隐藏，但**跑过存量补群的老任务也会有 `conversation_id`**，它们仍留着改版前的 `pending_pairing` 报名记录 —— 按 `conversation_id` 隐藏会让发布者**永远无法再选中这些人**（记录卡死）。因此实现改为 `claimPairCount = claimCount - memberCount > 0` 才给按钮：新版任务全员自动入队（差值为 0）→ 无按钮；老任务有待配对 → 保留按钮 + 黄条警告。求助型不受影响。
3. **黄条文案按「有没有任务群」分两种**：后端 `pair()` 只在任务已有 `conversation_id` 时才会 `joinIfAbsent` 把人拉进群，所以有群时说「自动把对方拉入该任务群聊」、没群时说「双方互相解锁联系方式，请通过联系方式对接」——不写后端做不到的承诺。
4. **弹窗文案不随功能开关切换**：`eggworld.features.task-auto-group` 置 `false` 会退回「报名进候选池 + 联系方式必填」的旧流程，但前端仍显示新文案（同 `2026-09-26_任务绑定群聊.md` 第八节 8.2「开关是止血、不是完整回滚」）。完整回滚要按第六节连前端一起换回旧版。
5. **小圆点用了新增样式 `.chat-dot`，没有直接复用 `.task-pending-badge`**：后者是带 `margin-left:auto` 的计数胶囊，塞进按钮里会把按钮内容推开；`.chat-dot` 是绝对定位在按钮右上角的小圆点，颜色与侧栏未读徽标一致（`#E8657E`）。
6. **有任务群时不再渲染单独的「我的搭子」入口**：与 §4「避免功能重复」同一取向 —— 主按钮「💬 进入群聊」已经覆盖，群侧栏本身可看成员。改版前**没有群**的组队任务仍保留「查看队友」名单弹窗（那是它们看队友联系方式的唯一入口）。
7. **认领成功弹窗只在任务确实有任务群时才弹**：卡片没带 `conversationId`（改版前遗留、且没跑过存量补群的教学/组队任务）时后端不会把认领者拉进群，此时退回一句 Toast，不承诺「已加入群聊」。
8. **红点依赖聊天室模块的会话列表**：未读数只存在于 `js/chatroom.js` 内部（`/api/chat/conversations` 的 `unreadCount`），主站通过 `window.chatroomUnreadOf(id)` 取值、聊天室在会话列表刷新后回调 `window.onChatroomUnreadChanged`（**单订阅位**，已加注释，后续若还有模块要听需改成数组/事件）。取不到时按 0 处理（不编造数据），因此**首屏极短时间内可能先无红点**，会话列表拉回后即自动补上；收到新消息（STOMP）也会触发刷新。
9. **求助型联系方式一律保留**：求助型没有任务群，发布者选中后只能靠联系方式对接，且 `4fb5c15` 刚把它改成「建议填写 + 空值软提醒一次」；本批只对教学/组队隐藏（发布表单与认领弹窗两处），并顺手让「隐藏时不再把带出的历史联系方式提交上去」。
