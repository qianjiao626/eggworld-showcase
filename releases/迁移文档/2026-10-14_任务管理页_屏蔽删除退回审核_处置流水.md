## 一、本次范围

新增一个**仅主管理员可见**的独立后台页面「任务管理」，补齐审核中心管不到的「已上线任务的处置能力」，并为每一次处置留痕。

本次之前：审核中心只能对**待审**任务做「通过 / 驳回 / 加精」，已上线任务既不能下架内容、也无法打回重审，且没有任何按人汇总查看内容的入口。

分块改动：

1. **任务处置**（主管理员专属，新增接口）
   - **屏蔽**：`hidden=1`，前台广场/搜索不再展示、不可被认领；数据完整保留、**可恢复**；屏蔽原因必填。
   - **恢复**：`hidden=0` 并清空处置原因。
   - **删除**：`deleted=1` 逻辑删除，前台与发布者都不可见，数据保留以便追溯；删除原因必填。
   - **退回审核**：`status='pending'` 并解除屏蔽，任务回到审核中心重新审。
   - **加精**：复用既有 `POST /api/admin/tasks/{id}/feature`，本页只做入口。
   - **资金在途保护**：状态为 `in_progress / full / submitted / completed` 的任务**不允许删除或退回审核**（会打断认领与蛋蛋币结算），提示引导改用「屏蔽」。
2. **处置流水**（新表 `task_governance_log`）：每次处置追加一条——谁 / 何时 / 对哪条任务 / 做了什么 / 为什么。同一条任务会被反复处置，只在任务行上盖「最后处置人」留不住过程。
3. **前台可见性收口**：`tasks` 表没有配 `@TableLogic`，此前 `deleted` 也没有被任何列表过滤。本次在**广场列表 / 任务详情 / 认领**三处显式加上 `deleted=0 AND hidden=0`，否则「屏蔽」只是个标记、内容照旧可见。
   - 详情页例外：**发布者本人**仍能打开自己被屏蔽/删除的任务。
4. **页面交互**：筛选（全部 / 分类 / 状态 / 关键词）、单行「主操作 + 更多」、必填原因的处置弹窗、点标题看只读信息（已屏蔽/已删除显示醒目的处置原因区块）、点发布者名下钻看该用户全部任务、处置记录弹窗、≤768px 的移动端适配（侧栏转底部 Tab、表格转卡片）。
5. **本页自测中发现并已修的两处缺陷**（同批随本次上线，本地真实浏览器 E2E 已验证）：
   - 点任务标题不弹窗：`state.records` 存的是原始 VO（任务 id 在 `vo.task.id`），但查找按 `state.records[i].id` 做，永远匹配不到，弹窗被静默 return。已改为在加载时一次性归一化。同一缺陷还让处置弹窗的目标行标题为空。
   - 发布者「我的 → 我的任务」看不到被屏蔽：卡片没读 `hidden` / `governanceReason`，被屏蔽任务仍显示「已审核 · 招募中」。已补红色「已屏蔽」标签与治理提示（含原因）。
