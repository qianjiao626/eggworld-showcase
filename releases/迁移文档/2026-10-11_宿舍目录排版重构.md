## 一、本次范围

只改宿舍目录的**展示排版与加载方式**，不改数据库、不改接口、不改审核与投稿规则。

改前的问题（浏览器实测确认）：

1. **列表卡片不可用**：只有一句来源标签（如「有第三方资料·待核实」），2321 所学校混在一起，无法挑出「真的写了房型」的学校。
2. **详情页顺序颠倒**：190px 装饰性「非宿舍实拍」占位封面排在最前，真资料被压到下面。
3. **信息被埋在长句里**：2851 条记录中 2548 条的 `description` 是「房型线索：…；床型线索：…」这类带标签文本，全塞进一行「资料摘要」。
4. **大量「待核实」堆砌**：字段缺失时统一显示「待核实」，形成一堵无信息量的墙。
5. **目录有 40 个重复校名**：`BL_SCHOOLS` 共 2361 条但唯一校名只有 2321 个。
6. **2.4MB 宿舍数据阻塞全站首屏**：`js/dormitory-facts.js`（gzip 约 143KB）在 `<head>` 同步加载，而数据只有宿舍页用得上。

改后：

- 列表卡片直接预览「房型 / 床型 / 卫浴」三行 + 记录条数；未命中显示「暂无可提取的房型信息」。
- 新增目录工具栏：五档筛选（全部 / 含房型·床型·卫浴 / 第三方资料 / 校方公开资料 / 仅线索·待补）+「有信息优先 / 目录原序」排序。
- 详情页改为「校名 → 证据概览徽标 → 按可用性排序的资料卡 → 用户投稿 → 占位封面（折叠到最底部）」。
- `description` 里的分段线索解析为独立标签条；校区/楼栋在字段有值时不再重复展示。
- 字段有值用绿色区分、缺失显示「未注明/待核实」。
- 渲染层对校名去重（不动共享的 `js/bl-schools.js`）。
- `js/dormitory-facts.js` 从 `<head>` 移除，进入宿舍页时按需加载；**首屏可交互后空闲预取**。

**为什么加空闲预取**：单纯按需加载会让「点进宿舍页」变慢（实测 1.5Mbps 下从基线 33ms 变成 1808ms）。预取后回到 49ms，首屏收益全部保留。
