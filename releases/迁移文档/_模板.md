## 四、部署步骤

<!-- 两部分都要写：① 本地生成部署包（打包机上的动作，很容易被漏）；② 服务器侧动作。
     只列与标准流程不同的部分也可以，但要能照着做；下面这些固定项不要缺 -->

**一、本地生成增量部署包**（在 PR 已合并进 `main` 之后执行；工作区必须干净、`HEAD` = 本次要发布的提交）

```powershell
git checkout main
git pull
powershell -ExecutionPolicy Bypass -File backend\build-deploy.ps1 -Name "<与本文档同名的上线名>"
```

- **基线**：脚本默认取最近一个 `release/*` tag（= 线上正在跑的版本）；若线上那一版**没有 tag**，必须显式加 `-Base <commit>`
- **产出** `releases/deploy/<上线名>/`：`backend/eggworld.jar`（后端有变更时脚本才重新 `clean package -DskipTests`；只改前端则只有前端文件）、`frontend/index.html`、本次变更的 `frontend/js/*.js`、`部署说明.md`
- **核对**「部署说明.md」：上传清单 / **删除清单** / jar 内版本信息；删除项必须与本文档第二节「文件删除」一致
- **敏感检查**：`jar tf releases\deploy\<上线名>\backend\eggworld.jar | findstr application`（应只有 `application.yml`）
- 备用全量打包（排查线上文件缺失等场景才用）：`backend\build-release.ps1` → `backend/release/`

**二、服务器侧（获授权后）**

1. **备份旧文件**（普通用户 `xiaos`，**禁止 `sudo` 建目录/拷文件**；建完立刻验证可读）
   - **先按本次主题建批次目录**：`~/eggworld/backup/<日期>-<主题>/`（`<主题>` 取本次上线名的关键词，一眼能认出是哪批，如 `2026-10-13-权限管理学生协管员`）；**库 dump 不放这里**，统一放 `~/eggworld/backup/db/`
   - 备份命令（把 `<...>` 替换成本次实际值；**本次会被覆盖的文件都要备一份**，只改前端就只备前端）：

   ```bash
   # ① 批次目录（名 = <日期>-<主题>，与本文档抬头「部署包 / 上线名」同源）
   BACKUP=~/eggworld/backup/2026-10-13-权限管理学生协管员
   mkdir -p "$BACKUP" ~/eggworld/backup/db

   # ② 旧的后端 / 前端文件（逐条列出本次会被覆盖的文件；只改前端时跳过 jar）
   cd /home/xiaos/eggworld
   cp eggworld.jar             "$BACKUP"/
   cp xs/index.html            "$BACKUP"/
   cp xs/js/admin-workbench.js "$BACKUP"/admin-workbench.js

   # ③ 库 dump（仅「含数据库变更」时执行；统一放 backup/db/，不放进批次目录）
   mysqldump --single-transaction --default-character-set=utf8mb4 --set-charset \
     eggworld > ~/eggworld/backup/db/eggworld_$(date +%Y%m%d_%H%M).sql
   chmod 600 ~/eggworld/backup/db/*.sql

   # ④ 验证可读（必做，不能省；属主必须是 xiaos，出现 root 就是错的）
   ls -l "$BACKUP" ~/eggworld/backup/db
   test -r "$BACKUP/eggworld.jar" && echo OK
   head -1 ~/eggworld/backup/db/eggworld_<本次时间戳>.sql   # 读得回内容才算有效备份
   ```

   - 读不回来的备份不算回滚点，**读不到就暂停发布**；上线目录只留**最近 3 次**，更早的按 [PROJECT_RULES.md](../../PROJECT_RULES.md) 2.3.4 的**归档判据**处理
2. **数据库迁移**（无库变更则跳过）：脚本先落到 `~/eggworld/sql/` → 执行 → 确认（见第三节）
3. **上传**：按包内「部署说明.md」
4. **重启服务**：`ssh xiaos@dsxnb.com 'systemctl restart eggworld'`
5. **版本自查**：`curl -s https://dsxnb.com/api/health` 的 `version` / `gitSha` = 本次上线名 / 本次 commit；后台侧栏底部一致
6. **删除项**：包内「部署说明.md」的删除清单**默认不执行**，留作回滚材料
