## 一、本次范围

把移动端的「每日签到」与「新手指引」两个入口，从「我的信息」页收进**任务广场（技能变现页）横幅**的动作条里，
减少"为了签到先离开广场页"的跳转；**web 端一动没动**。

背景：T4 那次把广场页顶栏整行去掉后，新手指引被挪到「我的信息」页的一行、签到被挪到同页的签到卡，
移动端两个高频入口都退到了二级页面。本次把它们放回广场首页。

具体改动：

1. **新增横幅动作条（仅移动端、仅技能变现页）**：横幅说明文字下方并排两个按钮
   ——「📅 每日签到」（金色实心）与「📖 新手指引」（白描边次级）。结构 `.banner-quick` 在
   `growth-schoolv3.html`，样式在 `js/plaza-mobile.css`。
   - 位置刻意放在 `.badges` **之外**：移动端那条 `.badges{display:none}` 会把里面的东西一起隐藏。
   - 桌面端 `.banner-quick` 基础规则是 `display:none`，web 端不出现任何新元素。
2. **签到按钮复用既有签到逻辑**：新按钮 id `checkinBtnPlaza` 并入 `checkinBtnList()`
   （原 `['checkinBtn','checkinBtnProfile']` → `['checkinBtn','checkinBtnPlaza']`），
   因此 `renderCheckin()` / `doCheckin()` 自动覆盖侧栏与横幅两处，零新增业务逻辑。
   同时把 `refreshCheckinStatus()` / `doCheckin()` 里"只对 `#checkinBtn` 写内联 display"的三处
   改为遍历 `checkinBtnList()` —— 否则游客与主管理员会在横幅上看到签到按钮。
3. **删除移动端旧入口**（都是移动端专属，桌面端无感）：
   - 「我的信息」页的 `.checkin-card` 签到卡（含 `#checkinBtnProfile`）与其 `#mine-panel-info .checkin-card*` 样式
   - 「我的信息」页的 `.moved-from-plaza` 新手指引行，以及 `js/plaza-mobile.css` 里它的两条规则
   - 主样式里 `.checkin-card{display:none}` 这条 base 规则
4. **同步测试**：`tests/daily-checkin.browser.js` 的移动端断言原本指向侧栏 `#checkinBtn`，
   而该按钮在 ≤768px 一直是 `display:none`（既有实现，不是本次引入），脚本在移动端段落必然报
   `Checkin clipped 360`。本次把移动端断言改到新入口，并补了「web 端动作条完全不出现」的断言。

取舍（已确认）：动作条**只放技能变现页**；「我的信息」页的两处旧入口**删除**，不保留重复入口。
