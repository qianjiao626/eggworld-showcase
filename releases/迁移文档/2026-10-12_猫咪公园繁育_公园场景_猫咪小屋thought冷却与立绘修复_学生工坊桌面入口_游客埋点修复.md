## 一、本次范围

在已上线的「猫咪小屋」（PR #34，移动端学生工坊子页）基础上，把**猫咪公园繁育**从开发分支推进到可上线状态，并顺带修复猫咪小屋的若干线上缺陷、修立绘透明破图、补猫咪信息区性别展示、给学生工坊加 Web 端入口、修游客首屏 401。按主题分块：

- **猫咪公园 · 繁育服务端权威（P0–P2）**：新增 `CatParkController` / `CatParkService` + 两张表 `park_cats` / `breeding_requests`。流浪猫可直接领养；用户猫由存档回写自动投影上公园（每人至多 3 只）；繁育走「申请 → 同意/拒绝」模型，**双方各自与自己猫的好感度 ≥ Lv.3 + 成年 + 均不在 48h 冷却**全部服务端校验，前端不可绕过；同意后**双方各领一只后代**（发起方 `offspring_breed_id`、归属方 `owner_offspring_breed_id`），领取按 `claimed_at` / `owner_claimed_at` 幂等；含异性校验与近亲检查（`parent_uids`）。
- **猫咪公园 · 公园场景固定 5 只**：新增 `GET /api/cat-park/scene` —— 2 只系统预设流浪猫（固定不动）+ 至多 3 只其他用户猫咪；**按用户去重**随机抽取（抽 3 个不同用户、每人取其公园猫中随机 1 只），**当前用户自己的猫不在自身视角展示**（仅对其他用户可见）；不足 3 人或某用户公园猫为 0 时按实际数量返回。前端 10s 轮询 + 事件驱动即时刷新：已展示的非流浪猫被主人带回家时立即重抽。
- **繁育好感度门槛上调 Lv.2 → Lv.3**：后端 `CatParkService.MIN_BREED_LEVEL=3`，SQL 注释、控制器注释、前端弹窗文案同步为 ≥3 级，前后端阈值一致。
