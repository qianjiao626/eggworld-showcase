## 一、本次范围

本批含两个主题，同一个 PR：

### A. 权限管理（学生协管员）

审核 / 看数据的活需要学生分担，但现有 `@AdminOnly` / `@ModeratorOnly` 两层角色太粗，无法只给单项能力。本次引入「**用户 → 权限点**」的两段式权限模型：

- **权限点写死在代码里**（`com.eggworld.common.PermCode`），首批两个：`content_review`（内容审核）、`data_dashboard`（数据看板）。主管理员 / 副管理员对所有权限点**隐式通过**，不落表 —— 保证不动现有主 / 副管理员逻辑。
- **数据模型**：新增 `user_permissions`（当前授权状态，唯一权威源）+ `permission_audit`（授予 / 收回审计，按人一条）。
- **后端门控**：新增 `@RequirePermission(permCode)` 注解；[`AdminAspect`](../../backend/src/main/java/com/eggworld/aspect/AdminAspect.java) 放行条件为 `isModerator() || 持有该权限点`，否则 403；`LoginUser` 增加 `permissions`，由新增的 `PermissionLoadInterceptor` **每请求回库加载**（沿用 `sub_admin` 的即时生效范式）—— **授权 / 收回即时生效，无需重登**。
- **受限既有接口**：审核中心相关接口（`AdminController` / `AdminGossipReportController` 的审核 GET / 驳回 / 隐藏 / 删除等）门控改为 `@RequirePermission(content_review)`、工作台数据接口（仪表盘 / 趋势 / KPI / 活动流 / 资金汇总等）改为 `@RequirePermission(data_dashboard)`；**发布官方任务、结算爆料奖励等仍维持 `@ModeratorOnly`，用户管理 / 封禁 / 风控等仍维持 `@AdminOnly`**。
- **后台「权限管理」页**（新增，**仅主管理员可见**）：搜索（用户名 / 昵称）+ 权限点 / 状态筛选 + 列表勾选 + 底部操作条「授予 / 收回选中 N 人」+ 逐行结果反馈（成功 / 跳过 / 失败带原因，**不做整体回滚**）+ 审计弹层（分页、时间倒序）。
- **学生端「协管」入口**：Web 侧栏新增「协管」tab、移动端「我的」页顶部新增「协管工作台」入口卡，**均仅持权学生可见**；进去是按其权限裁剪的轻量工作台（仅 `content_review` → 审核队列；仅 `data_dashboard` → 数据看板；两者都有 → 页内子 tab）。工作台**真复用**现有 `#page-reviewcenter` / `#page-dashboard` 区块（临时移入协管页插槽，离开移回），不重写 UI。
- **新接口**（均 `@AdminOnly`，独立 `AdminPermissionController`）：`GET /api/admin/permissions/codes`、`GET /api/admin/permissions/users`、`POST /api/admin/permissions/grant`、`POST /api/admin/permissions/revoke`、`GET /api/admin/permissions/audit`。
- **下发**：登录响应 / 用户信息接口增加 `permissions` 字段，供前端入口显隐；前端把 `enterManagerView()` / `switchRole()` 里写死的导航白名单改为读 `permissions`。

### B. 密码自助（改密 + 邮箱找回）

改密此前只能由管理员在后台操作；忘记密码没有入口。本次下放给用户：

- **登录 / 注册页「忘记密码」**：邮箱验证码（复用 `POST /api/auth/send-code`，一次性）+ 新密码 → `POST /api/auth/reset-password`（公开）。**邮箱不存在与验证码错误返回同一文案**（`邮箱或验证码不正确`），避免成为账号存在性探针。
- **「我的信息」页自助改密**：「账号安全」区块 → `POST /api/users/me/password`（需登录，校验当前密码确认本人操作，**不要求邮箱验证码**）。
- 两处新流程**沿用注册的密码规则**（6-20 位、字母 + 数字）；后端 `TextSanitizeConfig` 跳过净化字段补 `oldPassword` / `newPassword`（否则含 `& < ' "` 的密码会被改写成另一串）。
