## 一、本次范围

把验证码发信通道从「QQ 个人邮箱 SMTP」切换到「腾讯云邮件推送 SES」，解决个人邮箱账号级配额/风控导致用户收不到验证码的问题（问题记录见 [docs/email-quota.md](../../docs/email-quota.md)）。

- 移除 `spring-boot-starter-mail`，改用 `tencentcloud-sdk-java-ses` 调用 SES 的 `SendEmail` 接口
- SES 发信的两条硬约束（已按此落地）：**个人实名账号不再支持 SMTP 协议**（只能走 API）；**API 默认只支持模板发信**，模板需在控制台审核通过后用 `TemplateID` + `TemplateData` 传参
- 发信参数（发信地址 / SecretId / SecretKey / 模板 ID）走线上 `application-prod.yml`，不入库；未配置时降级为「验证码打印日志」
- 云 API 错误码翻译为可读业务提示（收件人错误 → 400；密钥/发信地址/模板问题 → 500 配置异常；限流/额度 → 稍后重试）
- 抽出发信公共层（`SesMailClient` + `MailScene` + 「场景 → 模板 ID」配置），支持多场景模板发信；验证码改为复用它
- 新增业务通知邮件能力，本次先落地「有人邀请你发布教学任务」场景（站内通知照旧，邮件是额外触达）
- 新增 13 个单测覆盖错误码映射、降级行为、通知开关与失败兜底

**不在本次范围**：`/api/auth/send-code` 的 IP 维度限流、注册前「邮箱已注册」拦截（仍留在 docs/email-quota.md 待办）；其余邮件通知场景待逐个补（每个场景都要在控制台新建模板并审核）。

## 七、备注 / 已知边界

- **线上配置不在部署包内**：`application-prod.yml` 未入库，需人工改。漏改的表现是日志出现 `[DEV] 未配置腾讯云 SES 发信参数，验证码不发送`，接口返回 200 但收不到信——与本次要解决的问题症状相同，排查时先看日志
- **模板属外部依赖**：验证码正文由控制台模板渲染，模板未审核通过时接口报 500「邮件服务配置异常」。改动 `eggworld.mail.code-expire-minutes` 必须同步改模板正文里的有效期文案
- **模板变量**：验证码场景用单个窄变量 `{{code}}`，主题固定为「【蛋蛋世界】邮箱验证码」，正文不能动态拼「N 分钟」
- **SES 仅支持 `ap-guangzhou` / `ap-hongkong`**：`region` 写其他值接口会报错
- **已做本地真实发信实测（2026-09-20）**：`POST /api/auth/send-code` 经 SES 真实发送成功（后端日志 `验证码已发送至 …`，非降级打印），**收件方已确认收到**，说明发信地址、密钥、模板、域名验证均生效；单测 191 项全通过（含本次净增 13 项）。**线上**仍需按验证清单复测
- **SES 不实时校验收件人是否存在**：向不存在的收件人发信实测同样返回 200（异步投递，失败发生在投递阶段）。因此「收件人不存在 → 400」的翻译只在参数非法等场景触发，**用户填错邮箱会静默失败**——这也是 docs/email-quota.md 待办①（注册前拦截已注册邮箱）更值得做的原因
- 发信域名 `dsxnb.com` 与验证码模板均已验证可用（由上述真实发送成功反证）；SPF / DKIM 仍建议按控制台提示配全以提升送达率
- 新增依赖 `tencentcloud-sdk-java-ses:3.1.1291`（传递引入 okhttp / gson / kotlin-stdlib），首次构建需联网拉取，之后 `mvn -o test` 可离线
- **通知邮件是异步的**：走独立的 `mailExecutor` 线程池（核心 1 / 最大 2 / 队列 200），队列满时丢弃并记日志；发信失败只记 `邀请通知邮件发送失败` 警告，**不影响邀请接口的成功返回**
- **通知邮件必须按场景建模板**：邀请场景的模板**名称**用 `蛋蛋世界教学任务邀请通知`、**类型**通知类，正文如下（变量 `{{inviterName}}` = 邀请人昵称、`{{skillList}}` = 技能方向，两个名字须与代码一致）：
  ```
  【蛋蛋世界】教学任务邀请通知

  你好！蛋蛋世界用户 {{inviterName}} 邀请你发布一条教学任务，需要你提供教学的技能方向是：{{skillList}}。

  请登录 dsxnb.com，在「消息通知」里查看任务详情，并决定是否接受这次邀请。

  如果这不是你期望收到的邀请，或是你暂时没有时间，直接忽略本邮件即可，不会对你的账号产生任何影响。
  ```
  模板未配或未审核通过时该场景静默跳过（只记 debug 日志），不影响业务。
- **模板审核口径（2026-09-20 实测）**：首版正文写「你收到一条新消息：{{content}}」被拒，理由是「变量 `{content}` 可填充范围过广，业务场景模糊，字数不足且结构不完整；通知类需 ≥40 字」。**可过审的形状 = 固定文案承担业务场景 + 变量只放字段级的值**（验证码模板 `{{code}}` 一次过审即为此形）；不要把整句自由文本塞进一个泛化变量。
- **邀请邮件有 24 小时去重**：同一邀请文案（含邀请人昵称与技能）24 小时内只发一封邮件，避免被反复点击刷掉 SES 配额、拉高投诉率；站内通知不受影响，仍然每次都发
