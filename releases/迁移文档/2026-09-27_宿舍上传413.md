## 一、本次范围

**问题**：用户在“补充宿舍照片”上传图片时，页面显示「网络异常，上传失败，请稍后重试」。
**根因（已线上实测）**：线上 Nginx 仍是 `client_max_body_size 2m`（server 级），仓库里为 `/api/dormitories` 单独放宽到 26m 的 location **从未部署到线上**。用户上传 >2MB 的图片时，Nginx 直接返回 **413 Request Entity Too Large**（HTML 错误页）；前端 `response.json()` 解析失败 → 落进 catch → 笼统显示“网络异常”。
**修复**：
1. 线上 Nginx：给 `/api/dormitories` 应用 `client_max_body_size 26m`（顶层仍保留 2m 的保守值），与后端 `spring.servlet.multipart.max-request-size: 26MB` 对齐。
2. 前端 `js/dormitory.js`：上传失败改为**显示真实原因**——413 明确提示“图片过大…”，401/403 提示重新登录，非 JSON 响应提示“服务器返回异常（HTTP xxx）”，不再一律“网络异常”。

**二、服务器侧（获授权后）**

1. 备份旧前端文件：`cp /home/xiaos/eggworld/xs/js/dormitory.js ~/eggworld/backup/2026-09-27-宿舍上传413/ && test -r ~/eggworld/backup/2026-09-27-宿舍上传413/dormitory.js`
2. 先**核对**线上 nginx 是否已有放宽规则：
   ```bash
   sudo nginx -T 2>/dev/null | grep -n -A2 'location = /api/dormitories'
   ```
   - 若已含 `client_max_body_size 26m;` → 无需改 nginx，跳到第 4 步。
   - 若缺失 → 在该 server 的 `/api/` 之前加入：
     ```nginx
     location = /api/dormitories {
         client_max_body_size 26m;
         proxy_pass http://127.0.0.1:8090/api/dormitories;
         proxy_http_version 1.1;
         proxy_set_header Host $host;
         proxy_set_header X-Real-IP $remote_addr;
         proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
         proxy_set_header X-Forwarded-Proto $scheme;
     }
     ```
     然后 `nginx -t && systemctl reload nginx`。
3. 上传新的 `js/dormitory.js`。
4. 自查：`curl -s https://dsxnb.com/api/health` 版本正常；页面强刷（`index.html` 不缓存、JS 有 7d 缓存，必要时提示用户强制刷新）。
