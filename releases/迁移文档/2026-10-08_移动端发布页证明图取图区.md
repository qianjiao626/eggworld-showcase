## 一、本次范围

**现象**（使用者报告）：手机上（≤768px）进入「发布任务」，**看不到「技能证明图片（选填）」取图区**，桌面端正常。

**根因**（已定位到代码）：移动端发布页不是靠 CSS 隐藏/显示，而是由外联脚本 `js/publish-mobile.js` 把桌面版式**重建**成 `.pm-body` 结构 —— 它按 `fieldOf(kids, id)` 从表单卡片的**直接子元素**里找字段块；而原实现是：

```js
function fieldOf(kids, id){
  return kids.filter(function(el){ return el.querySelector('#' + id); })[0] || null;
}
```

`Element.querySelector('#id')` **只匹配后代、不匹配元素自身**。`#publishProofWrap` 恰好是**表单卡片自己的直接子元素**（id 就在这个 div 上），于是 `fieldOf` 返回 `null`、`if(proofFld)` 为假 —— 这块**根本没被搬进移动版式**，页面上自然没有它。桌面端不做重建，所以只有手机中招。

**修复**：`fieldOf` 先看元素自身 id，再查后代：

```js
function fieldOf(kids, id){
  return kids.filter(function(el){ return el.id === id || el.querySelector('#' + id); })[0] || null;
}
```

**影响面**：仅 ≤768px 的发布页版式重建路径；桌面端、其它页面、后端与数据库均不受影响。同类字段里只有 `#publishProofWrap` 是「自身带 id」的直接子元素（其余 8 个查询都是 id 在后代上），所以只此一处中招，但已用测试把这个模式钉死，避免以后再踩。

## 七、备注 / 已知边界

1. **这类缺陷的通用教训**：移动端版式是「重建」而不是「隐藏」，任何**新增字段块**都必须确认 `js/publish-mobile.js` 会把它搬过去；`fieldOf` 的 id 查找现已覆盖「自身带 id」与「后代带 id」两种形态，并在测试里逐个校验 id 是否真实存在 —— 以后给发布表单加字段（或改名）会立刻变红，而不是等使用者在手机上发现。
2. **为什么桌面端没暴露**：桌面走主文件原生 DOM，不做重建；`#publishProofWrap` 一直都在。这也是本地此前只做过桌面验证、漏掉该场景的原因。
3. **本次不上传 `eggworld.jar`**：后端零改动；若部署包默认带了 jar，服务器侧可以选择不上传（不影响功能）。
4. **`?v=` 纪律**：改任何 `js/*`、`css/*` 都必须同步改 `index.html` 里的 `?v=YYYYMMDD`，否则「新 HTML + 旧 JS」或「旧 HTML + 新 JS」都会错位（本批已升 `publish-mobile.js` 到 `20261008`，其余文件版本号保持上线时那批不变）。
5. **与上一批的关系**：本修复是 10-07 那批「任务技能证明图片」的收尾缺陷修复，**不改变**该功能的任何口径（压缩阈值、接口、审核展示、改稿带图逻辑均不变）。
