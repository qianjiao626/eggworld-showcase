## 一、本次范围

两项用户反馈，都**不改数据库结构**：

1. **聊天室「发送」易误触成「帮助与反馈」（桌面端与手机端）**
   现象：点「发送」经常弹出反馈弹窗。
   根因：右下角反馈悬浮按钮 `.contact-fab` 与聊天室的输入区 / 「发送」按钮同处右下角，
   手机上尤其容易误触（拇指从输入区往右下角点「发送」时会蹭到它）。
   修复：**进入聊天室时隐藏该按钮，离开自动恢复**。
   - **双端生效**：规则置于全局作用域（不在 `@media` 内），桌面端与手机端行为一致
   - **按「实验室页」判断**：选择器为 `body:has(#page-lab.active) .contact-fab`，
     实验室后续会新增更多子项，页面级判断可一次覆盖全部子项，不必每加一个就回来补规则
   - **其他页保留入口**：任务广场、我的信息、榜单等页面按钮照常显示
   - **实测**（双端各 5 步切换，Chromium 真实渲染）：任务广场→可见 / 聊天室→消失 / 我的信息→恢复 / 再回聊天室→消失 / 榜单→恢复（两端一致）

   > 说明：像素级测量显示，该按钮与「发送」按钮**并未直接重叠**（手机端间距恒定 157px）；
   > 准确描述是「按钮侵入输入框右上角、与发送操作争抢触控区域」。

2. **私密群停用**
   原因：私密群「仅邀请」在没有好友体系支撑时容易变成小圈子，与校园广场的公开定位不符。
   三层处理：
   - **① 不允许新建**：`ChatGroupService.create()` 只接受 `public`，传 `private` 返回 400
   - **② 存量冻结为只读**：`ChatPermissionService.requireCanSend()` 拦截私密群发言（历史消息仍可查）
   - **③ 可选彻底解散**：`backend/sql/migrate-dissolve-private-groups.sql`（**默认不执行**，见第三节）

> ⚠️ **本次最大的风险点**：一对一私聊的 `visibility` 同样是 `private`。
> 任何一层拦截都**必须同时判 `type = 'group'`**，否则会把私聊一起禁掉。
> 代码与测试都已针对这点做了双重保护（见第五节）。

## 三、数据库变更

**结构变更：无。** 但提供了一个**可选的存量数据清理脚本**：

| 脚本 | 作用 | 是否必须执行 |
|---|---|---|
| `backend/sql/migrate-dissolve-private-groups.sql` | 把存量私密群置为 `dissolved`（从会话列表消失） | **不必须** |

**两种处理方式的取舍**：

- **只想冻结、保留历史可查** → **不要执行该脚本**。仅靠后端代码即可：私密群会显示在列表里，但发不了言。
- **想彻底清掉私密群** → 执行该脚本（群转 `dissolved`，不再出现在任何人的会话列表）。

若决定执行：

```bash
# 1. 先备份（必须先做）
mysqldump -u eggworld -p eggworld > ~/eggworld/backup/db/eggworld_$(date +%Y%m%d_%H%M%S).sql
chmod 600 ~/eggworld/backup/db/*.sql

# 2. 上传脚本到 ~/eggworld/sql/ 后，先看影响面（脚本第一条 SELECT）
mysql -u eggworld -p eggworld < ~/eggworld/sql/migrate-dissolve-private-groups.sql

# 3. 脚本末尾的校验 SELECT 应返回 remaining_private_groups = 0
```

> 脚本是**幂等**的（两条 UPDATE 都带 `status='active'` 条件），重复执行无副作用。
> 脚本**不含 DELETE**，数据保留可回溯。
> ⚠️ 执行顺序：**先建表/跑数据脚本，再切 jar**（本次无建表，但保持同一原则）。
> ⚠️ 永远不执行 `init.sql`（含 `DROP TABLE`）。
