## 一、本次范围

**要解决的问题（真实事故，2026-09-27）**：上一批「协作工作台三栏重构」上线后，**手机端页面整个错位**（列表头像变回 Emoji、两档切换器变成裸按钮、点进群聊中栏多出一条占位板压在聊天区上方）。

排查结论：**不是样式写错，是新旧文件混用**。

1. 线上静态资源的缓存策略不一致（实测响应头）：
   - `/`（index.html）→ `Cache-Control: no-cache`：**每次都会重新校验，永远拿新的**
   - `/js/chatroom.css`、`/js/chatroom.js` → `Cache-Control: max-age=604800`（**7 天**）+ `Expires`：**回过站的浏览器不会再校验**
   - → 部署前访问过站点的浏览器，会拿「**新 HTML + 旧 JS/CSS**」，上一批又刚好把聊天室的结构与样式全换了（新 HTML 的挂载点、`.chat-selected` 等类名旧 JS 不会设置），**必然错位**。桌面端强刷一次就正常，所以此前「强刷」的提示覆盖不到手机。
2. 已在真实视口复现（390×844，注入假数据）：干净环境下新代码在移动端是好的（三栏铺满、无溢出、输入区距底部导航仍有 17px、两档切换器满宽、列表⇄终端推拉正常）；**把 CSS/JS 换成旧版**后立刻复现出上述错位症状。

**本次改动**：给 `growth-schoolv3.html` 里**全部 30 个本地 `js/*.css|js` 引用**加上 `?v=YYYYMMDD` 缓存版本号（`?v=20260927`），并在文件头写明约定。上线时只要版本号变了，资源就是新 URL → **绕过旧缓存，用户不需要清缓存**。已注释停用的 5 个 deco/achievement 引用不动。

- 实测确认查询串不影响 nginx 的 `alias` / `try_files`：`curl -sI 'https://dsxnb.com/js/chatroom.css?v=20260927'` 返回 `200`，`Content-Length` 与不带查询串一致（27830）。
- 本地浏览器实测：23 个 `<script src>` + 7 个 `<link href>` 全部带上版本号，`chatroom.css` 正常加载、`window.chatroomRefresh` 正常挂载，控制台除「本地无后端」的 API 连接失败外无资源错误。

## 七、备注 / 已知边界

1. **约定：每次上线把 `v=` 后的日期改成上线当天**（文件头注释已写明）。忘改不会报错，只是那一次上线享受不到版本号带来的缓存隔离；改法：全文件替换 `v=20260927` → `v=<新日期>`。若希望彻底免人工，可让 `build-deploy.ps1` 在打包时把版本号写成上线名（本次未做，属可选加固）。
2. **只改了页面的引用，没动任何 js/css 文件内容**：因此本次上线的部署物只有 `index.html` 一个文件；`js/`、`assets/` 不上传。
3. **对上一批受影响的用户**：他们手机上缓存的仍是旧 URL（`js/chatroom.css`）→ 本次上线后新 HTML 引用的 URL 变成 `js/chatroom.css?v=20260927`，**浏览器会直接取新文件，无需清缓存**，这正是本次要达成的效果。
4. **没有改 nginx 缓存策略**（`/js/*` 仍是 `max-age=604800`）：本次用「换 URL」绕开它，不动线上配置。若以后希望 `js/` 一律立即校验，可另开一单改 nginx（按规范需单独授权）。
5. **`?v=` 只覆盖 HTML 里静态引用的资源**：本项目自有 `js/*.js` 里没有动态 `createElement('link'|'script')` 加载本地 js/css（已全仓核对，仅 `js/vendor/sockjs.min.js` 内部有无关的动态加载），所以不存在「漏网的资源」。
6. **本次验证范围**：本地 `node --test tests/*.cjs` 通过、本地浏览器加载无资源错误、线上带查询串返回 200 —— 均为**机器可核项**；**真实手机（微信）端未亲自复测**（本次改动本身只是换 URL，风险很低），上线后请按第五节第 3 条在手机上过一遍。
