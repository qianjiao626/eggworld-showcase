#### 3.1.1 「在原有表上加列」到底有哪几条（**易漏点，单独列出**）

这次**不只是建新表**，还在两张既有表上动结构；因为脚本里写成「探测 `information_schema` → `PREPARE/EXECUTE` 动态 SQL」，直接搜 `ALTER TABLE` **只会在引号里看到**，容易以为没有加列。实际共 **2 列 + 1 索引**，全部在 `migrate-task-proof-image.sql` 里：

| # | 语句 | 位置 | 判定条件 | 预期结果 |
|---|---|---|---|---|
| 1 | `ALTER TABLE tasks ADD COLUMN proof_image_id BIGINT NULL COMMENT '技能证明图片（…）'` | `migrate-task-proof-image.sql` 第 2 节 | `tasks.proof_image_id` 不存在才执行 | `tasks` 多一列 |
| 2 | `ALTER TABLE tasks ADD KEY idx_proof_image (proof_image_id)` | 同文件第 3 节 | `idx_proof_image` 不存在才执行 | `tasks` 多一索引 |
| 3 | `ALTER TABLE task_revisions ADD COLUMN proof_image_id BIGINT NULL COMMENT '修改稿的证明图片（…）'` | 同文件第 4 节 | `task_revisions.proof_image_id` 不存在才执行 | `task_revisions` 多一列 |

- **执行了 `migrate-task-proof-image.sql` = 这三条已经跑过**（除非条件判定为「已存在」而跳过，那也说明列/索引本来就在）。
- 逐条核对（任一为空就补跑对应那条）：
  ```sql
  SHOW COLUMNS FROM tasks LIKE 'proof_image_id';             -- 期望 1 行
  SHOW INDEX FROM tasks WHERE Key_name='idx_proof_image';    -- 期望 1 行
  SHOW COLUMNS FROM task_revisions LIKE 'proof_image_id';    -- 期望 1 行
  ```
