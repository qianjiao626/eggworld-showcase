# 真实未读通知数：协作汇报

日期：2026-09-14
分支：`fix/first-round-usability`

## 本次实现
- “我的任务”导航旁显示“未读 N 条”，0 条时隐藏。
- 数字来自现有通知接口的 `unread` 总数，即当前账号全部站内通知中 `isRead=0` 的数量；不是待办任务数，也不限于当前页 50 条。包含非任务类站内通知，不是任务专属计数。
- 我的任务顶部新增“查看通知”。打开面板不自动清空未读；点击某条通知才调用现有接口标记该条已读，成功后重新查询真实计数。支持手动“全部已读”。
- 页面可见且已登录时每 15 秒刷新；回到窗口、恢复页面可见、进入我的任务或打开通知面板时也刷新。属于轮询更新，不是 WebSocket 秒级推送。
- 通知支持翻页。请求失败保留最后一次成功计数，不伪装成已读；账号切换及乱序请求不覆盖新状态；登录失效清理缓存通知。
- 手机底栏角标及通知浮层做窄屏适配。

## 数据库影响
- 无表结构变更、无迁移、无初始化 SQL、无历史数据批量修复；后端代码和配置未改。
- 正常点击已读会通过现有接口更新当前账号通知的 `isRead`。因此不能理解为数据库完全没有写操作。
- 本次浏览器验证拦截后端接口并使用模拟数据，没有连接正式数据库。

## 验证结果
- 前端 Node 回归测试 13/13 通过：服务端总数、零隐藏、失败保留、单条/全部已读、账号切换、请求乱序、轮询、翻页、登录失效等。
- HTML 内嵌 JavaScript 语法检查通过，`git diff --check` 通过。
- Edge 浏览器使用模拟 API 验证：点击单条 6→5，全部已读 5→0；桌面 1280px、手机模拟宽度 360/390/430px 角标及浮层不越界，并留有截图。
- 尚未进行真实后端双账号端到端验收或实体手机验收；未合并 main，未正式上线。

## 伙伴验收
1. 合并前用隔离测试库的两个账号触发现有通知业务。
2. 接收者停留页面，观察通知计数在下次轮询更新；切回页面应立即请求刷新。
3. 打开通知面板不应清零；点一条未读后刷新页面，数量仍应减少；全部已读后角标隐藏。
4. 核对业务方是否要求只统计任务类通知。如需任务专属计数，应另行明确通知分类，不按文案猜测过滤。
