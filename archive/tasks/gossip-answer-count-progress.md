# 打听列表回答计数修复汇报

日期：2026-09-14

## 问题与原因
详情显示 3 个回答，列表卡片却显示 0。现有后端列表接口返回 `answerCount`，但不返回 `answers` 明细；前端映射丢弃 `answerCount`，卡片用空明细数组长度计数，导致错误显示 0。

## 修改
- 保留后端 `answerCount`，列表直接显示该总数。
- 仅当总数字段缺失时，兼容使用已有回答明细长度。
- 沿用原有发布回答成功后刷新列表和详情的逻辑，没有新增逐帖查询或改变业务规则。
- 只改前端，不改后端、数据库结构、评论内容或部署配置。

## 验证
- 先用回归测试复现：修复前新增 6 项中 3 项失败，实际渲染出错误的 0 回答。
- 修复后新增 6 项全部通过；加上通知测试，共 19/19 通过。
- 浏览器使用模拟 API 验证：列表与详情均显示 3；点击发布回答后，两处均变为 4。
- 内嵌 JavaScript 语法检查通过；提交前执行差异空白检查。
- 未对正式网站或真实数据库执行验收，未上线。伙伴发布新版前端后，应检查实际帖子列表与详情数量是否一致。
