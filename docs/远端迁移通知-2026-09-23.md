## 二、你这边需要做的（按你的情况选一条）

### A. 你现在有本地仓库（最可能）

```powershell
git remote add gitee https://gitee.com/xiaoshuai02/eggworld.git   # 若提示已存在就跳过
git fetch --all --tags
git branch --set-upstream-to=gitee/main main                      # 让 main 的 pull / push 走 Gitee
```

⚠️ 最后一条解决的是「主远端明明换成了 Gitee，`git pull` 却还去连 github.com、干等约 21 秒超时」——
不带参数的 `pull` / `push` 走的是**当前分支的 upstream**，而克隆自带的是 `origin`。
设置完 `git branch -vv` 里 `main` 那行应显示 `[gitee/main]`。（2026-09-24 补：发起方这边已设置过，你那边也要在自己的仓库里做一次。）

之后推送**显式写远端名**：

```powershell
git push gitee <你的分支>        # 日常推这个
git push origin <你的分支>       # 想让 GitHub 也有备份时再补一条
```

⚠️ **别用不带参数的 `git push`** —— 它推到的是分支的 upstream（多数分支还指着 GitHub），会又撞上连不通的问题。

### B. 新克隆（换机器 / 重装）

```powershell
git clone https://gitee.com/xiaoshuai02/eggworld.git
```

### C. 想彻底不用 GitHub（可选，但你得接受没有异地备份）

```powershell
git remote set-url origin https://gitee.com/xiaoshuai02/eggworld.git
```

## 三、协作流程里变了的四件事

| 事项 | 以前 | 现在 |
|---|---|---|
| 推送分支 | `git push origin <分支>` | **`git push gitee <分支>`** |
| 提 PR | GitHub | **Gitee**（描述模板 `.gitee/PULL_REQUEST_TEMPLATE.md`） |
| 推 tag | `git push origin --tags` | **`git push gitee --tags`** |
| 合并 | 双方确认后由人合并 | **不变**（仍然只由人确认执行，AI 不代合并） |

代码测试、迁移文档、上线流程这些**都没变**。
