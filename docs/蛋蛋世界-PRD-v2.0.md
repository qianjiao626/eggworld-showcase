## 1. 产品概述

蛋蛋世界（前身"成长学堂"）是一个面向大学生的互助成长平台，核心理念是"以任务驱动学习，以蛋蛋币激励互助"。学生通过发布或领取三种类型的任务（教学型、求助型、组队型）来积累经验和蛋蛋币，在互助中提升能力、结交伙伴。

> **关键数据一览：** 2 种用户角色 · 7 个学生端模块 · 3 种任务类型 · 6 大技能分类 · 5 级稀有度等级 · 10 张数据表

**核心价值：** 将大学校园里零散的"请教学长 / 帮同学做PPT / 找搭子自习"等行为结构化为任务流程，用蛋蛋币量化贡献、用经验值记录成长轨迹，用角色解锁体系增加趣味性和成就感。

## 2. 用户角色与权限

### 2.1 学生 (Student)

平台的主要使用者，通过发布和完成任务获得成长。

- 注册账号（仅学生身份，管理员不开放自注册）
- 浏览三个任务广场（技能变现 / 组队共创 / 求助中心），认领任务
- 发布教学型、求助型、组队型任务
- 认领任务时填写联系方式（选填，自动保存供下次使用）
- 确认配对、提交完成、双向评价
- 在八卦吃瓜模块发布打听、回答问题
- 查看个人蛋蛋币、经验值、稀有度、五维属性
- 在排行榜查看排名
- 提交反馈和联系客服

### 2.2 管理员 (Admin)

平台的运营者，管理任务和用户。

- 由系统预置或现有管理员创建
- 审核学生发布的任务
- 管理用户（查看进展、封禁/解封）
- 处理反馈工单，回复用户
- 查看数据统计概览

### 2.3 权限矩阵

| 功能 | 学生 | 管理员 |
|---|---|---|
| 浏览任务广场 | 可以 | 可以 |

## 5. 蛋蛋币与经验值系统

**设计理念：** 蛋蛋币是平台流通货币（可增可减，对应任务的经济激励），经验值是成长值（只增不减，等于成功发布/完成的任务数）。两个系统独立运作，蛋蛋币不能凭空创造，只能在用户间通过任务流转。

### 5.1 三种任务类型的蛋蛋币流向

| 任务类型 | 场景 | 蛋蛋币方向 | 到账时机 | 经验值 |
|---|---|---|---|---|
| 教学型 | 我教别人，别人来学 | 认领者 → 发布者 | 认领者提交完成时 | 双方各+1 |
| 求助型 | 我求帮助，别人帮我 | 发布者 → 认领者 | 发布者确认完成时 | 双方各+1 |
| 组队型 | 找搭子共同完成 | 发布者 → 认领者 | 双方确认完成后 | 双方各+1 |

**关键约束：** 蛋蛋币不能凭空创造。发布任务时如果需要支付蛋蛋币，系统先校验余额并冻结；任务取消或无人认领时，冻结的蛋蛋币退回原主。

### 5.2 等级体系

| 等级 | 名称 | 所需经验值 | 经验值区间 |
|---|---|---|---|
| 1 | 新手蛋 | 0 | 0 — 99 |
| 2 | 进阶蛋 | 100 | 100 — 299 |
| 3 | 达人蛋 | 300 | 300 — 599 |
| 4 | 大神蛋 | 600 | 600 — 999 |
| 5 | 传奇蛋 | 1000 | 1000+ |

### 5.3 蛋蛋币流水类型

| 类型 | label示例 | 说明 |
|---|---|---|
| earn | 完成任务 +X | 通过完成任务获得蛋蛋币 |
| spend | 认领任务 -X | 认领教学型任务时支付 |
| freeze | 发布任务冻结 -X | 发布求助/组队任务时冻结 |
| refund | 任务退回 +X | 取消或无人认领时退回 |
| reward | 悬赏采纳 +X | 打听回答被采纳 |
| publish_freeze | 发布打听冻结 -X | 发布打听时冻结悬赏 |

### 5.4 余额校验规则

- 发布任务时校验蛋蛋币余额是否足够，不足则提示"蛋蛋币不足"
- 认领教学型任务时校验余额（认领者需支付）
- 发布打听时校验余额（需冻结悬赏金额）
- 蛋蛋币和经验值必须从同一数据源读取，切换页面时自动刷新

## 6. 任务体系

### 6.1 四步闭环流程

三种任务类型遵循统一的"四步闭环"流程，但各步骤细节有所不同：

```
认领报名 → 确认配对 → 确认完成 → 双方互评
```

### 6.2 任务状态机

| 状态 | 说明 | 教学型 | 求助型 | 组队型 |
|---|---|---|---|---|
| 待确认配对 | 有人报名，等待发布者选择 | 有 | 有 | 有 |
| 进行中 | 配对确认，任务执行中 | 有 | 有 | 有 |
| 已提交 | 认领者提交完成，待验收 | 有 | 有 | 有（认领者先确认） |
| 已完成 | 最终完成，蛋蛋币已转账 | 有 | 有 | 有（双方确认后） |
| 已取消 | 协商取消或自动退回 | 有 | 有 | 有 |

### 6.3 评价规则

| 任务类型 | 评价方向 | 说明 |
|---|---|---|
| 教学型 | 学生 → 导师 + 导师 → 学生 | 学生提交完成时评价导师，导师反馈时评价学生 |
| 求助型 | 求助者 → 帮办者 | 仅发布者评价，帮办者不评价 |
| 组队型 | 发布者 ↔ 搭子 | 双方互评，确认完成时弹出评价窗口 |

**防重复评价：** 同一任务同一对评价者→被评价者只能评价一次。确认完成时不显示对方星级，通知和Toast提示不包含星级信息。

### 6.3.1 组队出资与互评（2026-09-15 工单口径）

- 发布者发布时出资 10 币，入选搭子配对时各出资 10 币；team 的 reward 固定为 10。
- 双方确认完成后进入原有 3 天互评期，到期调度退还每人 80%（8 币）；不是确认后即时到账。
- 退款不再要求均分达到 4 分；不评价、低分、高分退款相同，评价仍计入口碑。
- 已结算不重复发钱；未结算的存量已完成组队任务沿用新规则，不追补历史已结算资金。
- 审核驳回只退实际冻结额：help 退 reward、team 退 10、teach/reward 不退。

### 6.4 取消与退回机制

| 任务类型 | 取消方式 | 时间限制 | 退回规则 |
|---|---|---|---|
| 教学型 | 协商取消（待确认配对时直接取消） | 确认配对后48小时后需客服介入 | 冻结蛋蛋币退回原主 |
| 求助型 | 无手动取消 | 3天无人认领 | 自动退回 |
| 组队型 | 无手动取消 | **无报名截止**（90天兜底） | 长期招募，招满即止；超 90 天未成队才下架退回（2026-09-21 调整） |

### 6.5 联系方式可见性

- 认领者认领时填写联系方式（选填，自动保存供下次使用）
- 发布者可在配对管理弹窗和已发布任务详情页查看认领者联系方式
- 联系方式仅在确认配对后（进行中/已提交状态）显示，待确认配对状态不显示
- 发布者联系方式在配对成功后对认领者可见
- 联系方式标记为黄色 📞 标签

|---|---|---|---|

| 就业技能 | job | 简历优化、面试辅导、职业规划 | #2196F3 |
| 副业技能 | side | 自媒体、电商、设计接单 | #FFD700 |

## 9. 打听/八卦模块

八卦吃瓜模块（F14）是一个悬赏问答社区，用户可以发布打听问题并设置悬赏蛋蛋币，其他用户回答后由发布者采纳最佳回答。

### 9.1 核心流程

```
发布打听（扣冻结蛋蛋币） → 用户回答 → 采纳回答（悬赏到账）
```

### 9.2 规则

| 规则 | 说明 |
|---|---|
| 发布打听 | 填写标题、描述、悬赏金额；发布时冻结对应蛋蛋币；余额不足不可发布 |
| 回答 | 任意用户可回答，无数量限制 |
| 采纳 | 发布者选择最佳回答，悬赏蛋蛋币转入回答者账户 |
| 自动退回 | 发布1个月（30天）无人回答，自动退回冻结蛋蛋币 |
| 永久保留 | 提问永久保留，退回后仍可回答但无悬赏 |
| 用户主动取消 | 已移除，仅支持自动退回 |

## 10. 数据模型

系统共 10 张数据表，基于 MySQL 8.0+，字符集 utf8mb4。

| 表名 | 说明 |
|---|---|
| users | 用户表：昵称/角色/蛋蛋币/经验值/获赞数/口碑值/蛋类型/稀有度 |
| user_stats | 五维属性表：学识/打工/魅力/搞钱/口碑 |
| tasks | 任务表：类型(teach/help/team)/技能分类/蛋蛋币/认领模式/最大人数/状态 |
| task_claims | 任务认领表：认领者/状态/联系方式/配对时间/提交时间 |
| ratings | 评价表：评价者/被评价者/星级/评论（唯一约束防重复） |
| point_logs | 蛋蛋币流水表：类型/变动金额/变动后余额/关联任务 |
| gossip_posts | 打听帖子表：标题/描述/悬赏/冻结状态/采纳状态/截止时间 |
| gossip_answers | 打听回答表：内容/点赞/是否采纳 |
| notifications | 通知表：用户ID/内容/类型/已读状态 |
| feedback_tickets | 反馈工单表：内容/联系方式/状态/管理员回复 |

### 10.1 建表 SQL

#### 10.1.1 用户表 users

```sql
CREATE TABLE users (
  id BIGINT PRIMARY KEY AUTO_INCREMENT,
  nickname VARCHAR(50) NOT NULL UNIQUE COMMENT '昵称',
  email VARCHAR(100) COMMENT '邮箱',
  phone VARCHAR(20) COMMENT '手机号',
  password_hash VARCHAR(255) COMMENT '密码哈希',
  role ENUM('student','admin') DEFAULT 'student',
  school VARCHAR(100) COMMENT '学校',
  major VARCHAR(100) COMMENT '专业',
  city VARCHAR(50) COMMENT '城市',
  grade VARCHAR(20) COMMENT '年级',
  age INT COMMENT '年龄',
  bio TEXT COMMENT '个人简介',
  mbti_type VARCHAR(4) COMMENT 'MBTI类型',
  mbti_group VARCHAR(2) COMMENT 'MBTI分组: NT/NF/SJ/SP',
  points INT DEFAULT 100 COMMENT '蛋蛋币余额',
  exp INT DEFAULT 0 COMMENT '经验值（完成任务数）',
  likes INT DEFAULT 0 COMMENT '获赞数',
  reputation DECIMAL(2,1) DEFAULT 0.0 COMMENT '口碑值（评价均分）',
  egg_category VARCHAR(20) COMMENT '蛋类型分类',
  egg_rarity ENUM('N','R','SR','SSR','UR') DEFAULT 'N',
  invite_code VARCHAR(20) COMMENT '邀请码',
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
  updated_at DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
);
```

#### 10.1.2 用户统计表 user_stats（五维属性）

```sql
CREATE TABLE user_stats (
  user_id BIGINT PRIMARY KEY,
  knowledge DECIMAL(2,1) DEFAULT 0 COMMENT '学识值 0-10',
  skills DECIMAL(2,1) DEFAULT 0 COMMENT '打工值 0-10',
  charm DECIMAL(2,1) DEFAULT 0 COMMENT '魅力值 0-10',
  money DECIMAL(2,1) DEFAULT 0 COMMENT '搞钱值 0-10',
  reputation DECIMAL(2,1) DEFAULT 0 COMMENT '口碑值 0-5',
  FOREIGN KEY (user_id) REFERENCES users(id)
);
```

#### 10.1.3 任务表 tasks

```sql
CREATE TABLE tasks (
  id BIGINT PRIMARY KEY AUTO_INCREMENT,
  title VARCHAR(200) NOT NULL COMMENT '任务标题',
  description TEXT COMMENT '任务描述',
  task_type ENUM('teach','help','team','reward') NOT NULL COMMENT '任务类型',
  -- 后续字段以实际后端建表语句为准，此处为原型阶段截取
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
  updated_at DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
);
```
