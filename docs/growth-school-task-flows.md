# 三大广场任务认领交互流程分析

文件：`growth-school.html`

---

## 一、蛋蛋拜师学艺（教学型 teach 任务）

### 1.1 认领按钮点击事件

| 层级 | 按钮文字 | 触发函数 | 行号 |
|------|---------|---------|------|
| 广场卡片 | "查看详情" | `bindDetailBtn` → `showTaskDetail` | L5292, L5114 |
| 详情弹窗 | "认领任务" | `claimFromDetail()` | L5244 |

**点击流程：**
1. 用户点击广场卡片上的"查看详情"按钮 → `bindDetailBtn` 绑定的点击事件（L5292-5298）
2. 校验是否已注册，未注册则弹出注册弹窗
3. 已注册则调用 `showTaskDetail(btn)`（L5114），打开任务详情弹窗
4. 详情弹窗底部显示"认领任务"按钮（L5229），点击触发 `claimFromDetail()`

### 1.2 认领后的状态变化

`claimFromDetail()` 函数（L5244-5291）执行以下操作：

1. **加入"我的任务"列表**：调用 `addToMyTasks()`（L5260），新建卡片状态为"已认领"、进度 0%
2. **登记认领者**：将当前用户信息 push 到 `TASK_CLAIMERS[taskName]` 数组（L5262-5270），状态为"进行中"
3. **发送通知**：给发布者推送认领通知（L5273）
4. **更新卡片数据**：`data-claimed` +1，进度条和认领人数文本更新（L5274-5288）
5. **toast 提示**："认领成功，已加入「我的任务」"（L5289）

教学型任务支持**单人/多人**两种认领模式：
- 单人模式（`data-claim-mode="single"`）：满员后按钮变灰，显示"已满员"
- 多人模式（`data-claim-mode="multiple"`）：按最大人数限制

### 1.3 是否有确认配对环节

**无显式确认配对环节。** 教学型任务采用"先到先得"机制：
- 单人认领：第一个点击认领的人直接配对成功
- 多人认领：按顺序认领直到满员
- 发布者视角的教学型任务卡片上**没有**"选择帮办"按钮（对比求助型有此按钮）

### 1.4 是否有确认完成环节

**有，分为两步：**

**第一步：认领者提交完成**
- 我的任务卡片上点击"提交完成情况" → `completeTask(btn)`（L5302）
- 按钮文字变为"已提交，等待批改"，按钮禁用（L5337）
- 同时扣除/增加蛋蛋币：教学型任务中认领者**支付**蛋蛋币（L5326-5327）
- 增加经验值 +10
- 发送通知："任务已完成提交，等待批改"

**第二步：发布者批改反馈**
- 我发布的任务卡片上点击"反馈" → `reviewMyTask(btn)`（L5520）
- 打开"反馈学伴提交"弹窗，列出所有提交者及其状态
- 对"已提交"状态的学伴，点击"反馈并评价" → `confirmReviewAndRate(idx)`（L5557）
- 关闭批改弹窗，弹出评价窗口

### 1.5 是否有互评/评价功能

**有完整的双向互评机制：**

1. **认领者方向**：`completeTask` 提交后延迟 800ms 自动弹出评价（L5377-5382）
   - 调用 `openRating(taskName, taskType, true)`，`isClaimer=true`
   - 评价对象：任务发布者
   - 评价维度：教学/帮助质量

2. **发布者方向**：`confirmReviewAndRate` 后延迟 600ms 弹出评价（L5564-5566）
   - 调用 `openRating(name, taskType, false)`，`isClaimer=false`
   - 评价对象：任务完成者
   - 评价维度：任务完成质量

3. **评价提交**：`submitRating()`（L3643-3669）
   - 星级评分（1-5星）+ 文字评价（选填）
   - 模拟对方也给你打分（互惠评价，L3654-3659）
   - 更新口碑值（所有收到评价的平均分，L3660-3663）
   - 可以跳过评价：`skipRating()`（L3671）

## 二、蛋蛋要求助（求助型 help 任务）

### 2.1 认领按钮点击事件

| 层级 | 按钮文字 | 触发函数 | 行号 |
|------|---------|---------|------|
| 广场卡片 | "查看详情" | `bindDetailBtn` → `showTaskDetail` | L5292, L5114 |
| 详情弹窗 | "认领任务" | `claimFromDetail()` | L5244 |

**点击流程与教学型一致：** 卡片 → 详情 → 认领

### 2.2 超额报名和指派逻辑

**核心逻辑：求助型任务支持超额报名，不受名额限制**

代码依据（L5225, L5257）：
```javascript
// 只有非 help 且非 team 的任务才检查满员
var isFull = taskType !== 'help' && taskType !== 'team' && maxC && claimed >= parseInt(maxC);
// claimFromDetail 中同样：
if(taskType !== 'help' && taskType !== 'team' && maxC && claimed >= parseInt(maxC)){ toast('报名名额已满'); return; }
```

**发布者指派流程：**
1. 我发布的任务卡片上点击"选择帮办" → `openClaimerManager(this)`（L4991）
2. 打开认领管理弹窗，显示所有认领者列表（头像、MBTI、蛋类型、稀有度、口碑值、简介、状态）
3. 点击认领者卡片切换选中状态 → `toggleClaimerSelect(elem)`（L5055）
4. 底部显示"已选 N 人" → `updateClaimerSelectedCount()`（L5065）
5. 点击"确认指派" → `confirmAssign()`（L5072）
   - 校验至少选 1 人
   - toast 提示"已指派 N 人完成任务"
   - 发送通知
   - 关闭弹窗

### 2.3 是否有确认配对环节

**有。** 求助型任务采用"超额报名 + 发布者选择指派"模式：
- 任何人都可以报名（无名额限制）
- 发布者在认领管理弹窗中查看报名者的技能等级与口碑值
- 发布者多选后确认指派，被选中的人正式开始任务

### 2.4 是否有确认完成环节

**有，与教学型相同的两段式流程：**

1. **认领者提交**：`completeTask(btn)`（L5302）
   - 求助型任务中认领者**获得**悬赏蛋蛋币（L5328-5331）
   - 蛋类型匹配时 ×1.2 加成
   - 状态变为"已提交，等待批改"

2. **发布者批改**：`reviewMyTask(btn)` → `confirmReviewAndRate(idx)`
   - 查看提交列表，点击"反馈并评价"

### 2.5 是否有互评/评价功能

**有，与教学型完全相同的双向互评机制：**
- 认领者提交后自动弹出评价（L5378）
- 发布者批改后弹出评价（L5565）
- 通过 `submitRating()` 提交，影响口碑值
- 评价弹窗中任务类型显示为"求助型"（L3613）

## 三、蛋蛋要组队（组队型 team 任务）

### 3.1 报名组队按钮点击事件

| 层级 | 按钮文字 | 触发函数 | 行号 |
|------|---------|---------|------|
| 广场卡片 | "报名组队" | `bindDetailBtn` → `showTaskDetail` | L5292, L5114 |
| 详情弹窗 | "报名组队" | `claimFromDetail()` | L5244 |

**按钮标签差异化**（L5226）：
```javascript
var claimBtnLabel = taskType === 'team' ? '报名组队' : '认领任务';
```

### 3.2 选择候选人逻辑

**超额报名**：与求助型相同，组队型任务不受名额限制（L5225, L5257）

**发布者选搭流程：**
1. 我发布的任务卡片上点击"选择搭子" → `openClaimerManager(this)`（L4991）
2. `openClaimerManager` 根据 `taskType === 'team'` 调整 UI（L5002-5016）：
   - 标题："搭子管理 — "（原为"认领管理 — "）
   - 提示文案："查看报名者的技能等级与口碑值，选择你的蛋蛋要组队（可多选，选择后任务开始）"
   - 确认按钮文字："确认选搭"（原为"确认指派"）
3. 候选人列表展示：头像、蛋类型、稀有度、⭐口碑值、简介、状态
4. 多选逻辑：`toggleClaimerSelect(elem)`（L5055）
5. 确认选搭：`confirmAssign()`（L5072）

### 3.3 是否有双方确认环节

**有，组队型任务有独立的双方确认完成机制：**

**参与者（搭子）方确认：** `teamConfirmComplete(btn)`（L5781-5808）
- 点击"确认完成"按钮
- 状态标签变为"等待发布者确认"，颜色变为 #00897B
- 按钮变为"已确认完成"（禁用，绿色背景）
- 新增提示："你已确认完成，等待发布者确认。双方确认后 N 蛋蛋币将自动到账。"
- 发送通知："你已确认完成组队任务，等待发布者确认"

**发布者方确认：** `teamPublisherConfirm(btn)`（L5811-5841）
- 点击确认按钮
- 状态标签变为"已完成 · 双方确认"，颜色为绿色
- 按钮变为"已完成"（禁用，绿色背景）
- 提示更新为："双方已确认完成，N 蛋蛋币已转移给搭子。"
- 发送通知："组队任务双方确认完成，N 蛋蛋币已释放给搭子"

### 3.4 是否有确认完成环节

**有，与 teach/help 模式不同，组队型走独立的双方确认路径：**

| 对比项 | 教学型/求助型 | 组队型 |
|--------|-------------|--------|
| 完成函数 | `completeTask()` | `teamConfirmComplete()` + `teamPublisherConfirm()` |
| 确认机制 | 单方提交 + 发布者批改 | 双方确认（搭子先确认 → 发布者确认） |
| 蛋蛋币时机 | 提交时即结算 | 双方确认后才从冻结中释放 |
| 经验值 | 提交时 +10 | 代码中未见经验值增加逻辑 |

### 3.5 是否有互评/评价功能

**组队型任务的互评功能未明确实现：**

1. `completeTask` 中的自动评价触发**不包含** team 类型（L5378）：
   ```javascript
   if(taskType === 'teach' || taskType === 'help'){
     setTimeout(function(){ openRating(taskName, taskType, true); }, 800);
   }
   ```

2. `openRating` 函数中的任务类型显示只处理 teach/help（L3613）：
   ```javascript
   info.textContent = '任务：' + taskName + '（' + (taskType==='teach'?'教学型':'求助型') + '）';
   ```

3. `reviewMyTask` 虽然有 team 类型的显示，但 `confirmReviewAndRate` 仍调用 `openRating`，此时传入 team 类型会显示异常（显示为"求助型"）

**结论：组队型任务的互评功能在当前代码中不完整或未实现。**

## 五、三种任务类型对比总结

| 对比维度 | 教学型（teach） | 求助型（help） | 组队型（team） |
|---------|---------------|---------------|---------------|
| 广场名称 | 蛋蛋拜师学艺 | 蛋蛋要求助 | 蛋蛋要组队 |
| 认领按钮 | 认领任务 | 认领任务 | 报名组队 |
| 报名限制 | 受名额限制（单人/多人） | 超额报名，不受名额限制 | 超额报名，不受名额限制 |
| 配对方式 | 先到先得，自动配对 | 发布者从报名者中指派 | 发布者从报名者中选搭子 |
| 认领管理弹窗 | 无（教学型发布者无"选择帮办"按钮） | 有，"选择帮办" | 有，"选择搭子" |
| 完成函数 | `completeTask()` | `completeTask()` | `teamConfirmComplete()` + `teamPublisherConfirm()` |
| 完成确认 | 认领者提交 → 发布者批改 | 认领者提交 → 发布者批改 | 搭子确认 → 发布者确认（双方确认） |
| 蛋蛋币流向 | 认领者支付 → 发布者收取 | 发布者悬赏 → 完成者获得 | 发布者冻结 → 双方确认后搭子获得 |
| 互评功能 | 有（双向） | 有（双向） | 不完整/未实现 |
| 口碑值影响 | 是 | 是 | 否（未关联） |
